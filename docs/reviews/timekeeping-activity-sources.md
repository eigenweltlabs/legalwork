# Timekeeping evidence and device history

## What reaches a suggestion

Each scheduled or manual run gathers the enabled sources for the active Back Office account and selected local date. The server writes the observations to a private day file before asking the selected model to group them. The model can group corroborating events, split a timed source, suggest independently supported work in parallel, or leave a duration open. The worker reviews the resulting drafts, edits minutes and billing details, then accepts or dismisses each suggestion.

| Source | What LegalWork actually sees | Time it can support |
| --- | --- | --- |
| LegalWork project calendar | Uses the project calendar’s event title, time and project. Imported iCalendar invitations match the signed-in email against the organizer and guests, including changes to a single recurring occurrence. A decline, delegated invitation or non-participant role excludes that occurrence. An explicit assignment to the worker or an unassigned work block with no guest list can also qualify. | The elapsed interval is a proposed duration. The worker confirms attendance. An all-day event supplies context without minutes. |
| Google Calendar and Outlook Calendar | Primary calendar, owned secondary calendars and shared calendar copies accessible to this account. A shared event must identify the worker as an attendee or organizer. The collector discards guest addresses after checking participation. Declines, cancellations, out-of-office and Google location or birthday entries are excluded. Matching iCalendar occurrences across feeds have one inference identity. | Only the elapsed part of a scheduled appointment can support suggested minutes. The worker confirms attendance. All-day events have no measured duration. |
| Gmail and Outlook mail | Sent and received message subjects, timestamps and hashed message/thread identifiers. Gmail uses mailbox labels and Microsoft uses the sent folder and sender identity, including messages moved to other folders. Drafts, junk, deleted and unsent messages are excluded. Message bodies, recipient lists and attachment contents are absent from the log. | A sent message dates a worker action. A delivered message supplies context only for a reply in the same thread. Receiving mail or the current read flag cannot establish reading time. |
| LegalWork tasks | Human task updates, notes and attachments through supported project and Back Office routes, plus synced notes attributed to the signed-in user. No dedicated external Google Tasks, Microsoft To Do or Asana connector is registered. A task due date can exist without any user action. | A dated action with no measured duration. |
| Google Drive, OneDrive for work or school and SharePoint | Explicitly enabled file accounts. Google supplies the signed-in user's latest modification time. Microsoft work or school file metadata must attribute a modification to the signed-in drive owner. A previously observed edit remains available when a later query returns only a newer edit of the same file. | One dated modification per observed timestamp. A file's name, size, existence or other people's changes cannot establish this worker's time. |
| LegalWork document saves | Human saves in supported project editors, explicit imports, copies, attachments and storage uploads. Wiki page edits, revision restores, uploads and human-published project contributions also supply a filename, project and timestamp. Wiki page evidence omits the body. A conflict or an unchanged page save contributes nothing. | A dated action. Saving or uploading a file supplies no measured working duration. |
| OneDrive Personal | Explicit opt-in initializes the provider's change cursor on the first successful check. Later scans record only file changes attributed to this account. Disabling the source ends that collection period. | Dated prospective changes. Earlier activity before the cursor, and the disabled period, cannot be reconstructed. |
| Earlier local document use | Explicit date and native single-folder selection. macOS reads Spotlight last-used time for documents directly inside the selection. Windows checks retained Shell Recent shortcuts explicitly pointing to documents in the selection and carrying a visit time. | Private filename and timestamp only. No worked minutes or matter inferred from one opening. OS records can be absent or overwritten by a subsequent use. |
| Meeting recordings | A separate opt-in before starting a retained LegalWork desktop recording captures its title, initially linked project and start and stop times. Only successfully completed live recordings qualify. Audio, transcripts, summaries, imported media and one-shot dictations are excluded. | The capture interval supports a proposal for human review. A matching calendar entry can corroborate the same meeting. |
| Desktop activity | Opt-in per profile. A running desktop client samples the active application and device idle/lock state. A native provider can supply an explicit local document basename when permission allows. Repeated matching active samples form one local run. | Sampled foreground use. A single sample, a changed app, an idle or locked device, or a gap longer than 45 seconds contributes no inferred time between those samples. |
| LegalWork workspace activity | While the renderer is running, it samples project, stream, foreground, passive or running-agent status. Focus, visibility and recent input determine active intervals. Overlapping focus notifications from multiple windows resolve to a single foreground window. | Foreground intervals support suggested time. Passive windows and concurrent agent jobs supply context. Agent runtime alone cannot establish the worker’s time. |
| Matter stopwatch | Start, stop, selected matter, local dates and measured seconds. Starting or stopping a timer is explicit. | The complete stopped interval. **Always show** offers it directly for review. The day log retains the original in either mode. **Use as an AI source** also gives it to the model for grouping. |

The workspace file browser uses the same explicit file actions for Box, Dropbox, SMB, WebDAV, S3, Azure Blob Storage, Google Cloud Storage, SFTP, FTP and linked roots. It observes operations performed in LegalWork. These transports expose no common history identifying which person edited an external file. A folder listing, recent modification time or sync pass does not establish a personal work event.

The account’s private runtime directory contains the original task, desktop and workspace observations in UTC-day partitions, document-save records, timer originals, and the worker’s accepted or edited proposals. Each source check writes `private-timesheets/<profile>.json.day-log/YYYY-MM-DD.json` with the local date, time zone, collection boundary and normalized observations. Source identities and clock ranges tie drafts back to observations. These files stay in the local runtime. Selecting a connected model sends the necessary evidence to that model for inference. The grouping pass receives dated observations across the day. Wording requests receive only the selected scope’s observations, billing context and applicable document history.

The journal keeps changed and withdrawn observations with the time they were replaced. Repeated reads reuse unchanged observation identities. For an unavailable feed, its last successful observations remain marked as stale by the account failure. Only newly verified feeds reach inference in that run. A model failure leaves the journal intact. A partial provider read leaves the coverage boundary unchanged, identifies the account that failed and allows unaffected accounts to produce drafts. Retry reads the authenticated sources again. A calendar cancellation withdraws an occurrence. Earlier file edits already witnessed by LegalWork are retained for an enabled, successfully checked account. There is no automatic journal expiry.

### Enabling and verifying connected sources

In **Settings > Integrations**, connect Gmail or Outlook for messages and activate Google Calendar or Outlook Calendar for appointments. In **Settings > Time tracking**, enable each desired source. Mail and calendar have separate switches, including Outlook integrations sharing a sign-in. File metadata readers require a separate opt-in for each account. The native connector registry supports one credential per provider. Google and Microsoft accounts can run together. Settings displays a provider-verified account name from a successful scan, or a short account identifier before the first scan.

The native Google OAuth configuration requests Gmail read or modify access for mail, and calendar-list read plus event read or write for Google Calendar. Outlook requests delegated User.Read, Mail.Read or Mail.ReadWrite, and Calendars.Read or Calendars.ReadWrite. These allow the mailbox profile and shared calendar copies already present in that mailbox. Reading directly from another person's mailbox requires different Microsoft permission. The collector only visits calendars exposed through the signed-in account. Tenant restrictions, a narrower managed grant, an inaccessible calendar or incomplete guest information can restrict results. A refused shared calendar is skipped while other accessible calendars continue. [Google calendar lists](https://developers.google.com/workspace/calendar/api/v3/reference/calendarList/list) · [Google event fields](https://developers.google.com/workspace/calendar/api/v3/reference/events) · [Microsoft calendar sharing](https://learn.microsoft.com/en-us/graph/outlook-get-shared-events-calendars) · [Microsoft delegated profile permissions](https://learn.microsoft.com/en-us/graph/api/user-get?view=graph-rest-1.0)

Mail collection follows provider pages and requests message metadata. Outlook sender identity is compared locally and then discarded. An archived incoming message remains a receipt. The same Internet Message-ID links matching representations without storing the original identifier. The per-account collector times out and reports incomplete checks on provider throttling or exceeded page limits. The user can retry, and another scheduled check can collect later. Individual messages disappearing during a Gmail page read are skipped. The app makes no attempt to infer a message-open timestamp from a read flag. [Gmail message metadata](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages) · [Gmail pagination](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/list) · [Graph mailbox listing](https://learn.microsoft.com/en-us/graph/api/user-list-messages?view=graph-rest-1.0) · [Graph message fields](https://learn.microsoft.com/en-us/graph/api/resources/message?view=graph-rest-1.0)

The synthetic integration test exercises the actual account registry, credential broker, native authenticated HTTP transport, workday route, scheduler and private journal. It verifies Google and Microsoft accounts together, sent and archived received mail, second pages, owned and shared appointments, decline and canceled filtering, account toggles, a throttled mailbox, and recovery. Those provider responses are fixtures. A separate read-only check on the review Mac retrieved a delivered message through the signed-in Outlook connector and verified its source, direction, observation date and private journal permissions. Two dates without messages produced zero mail observations. The live check kept message contents and account details out of the test reports.

A Mac integration run used the installed Gemma 12B model through the bundled OpenCode engine. An isolated account imported two real Spotlight last-use observations for test documents, saved and amended a project document, created a task and ran a matter stopwatch for 65 seconds. The second import added zero duplicate events. The six original observations yielded two drafts that survived reloading the workday. The document work had no recorded duration. The timer had one recorded minute. Nothing was booked.

### Overlap and estimates

- A client call from 09:00 to 10:00 and active drafting for a different matter from 09:30 to 09:45 can produce two separate suggestions. The claims for the meeting and drafting are independent. Reviewing and accepting one leaves the other available. Two representations of the same meeting or the same portion of a stopped timer still share a claim and cannot be booked twice.
- A memo save followed by an email sending the revised memo can support an editable estimate. The estimate carries a reason and original source references. The unmeasured start, end and recorded minutes stay empty in the original. The timekeeper can accept the estimate, replace it or dismiss the draft. The elapsed gap between the two events does not establish continuous work.
- Automatic estimates require distinct dated human actions or a dated human action with a substantive change summary. As implemented, ordinary file saves supply no change summary. A single file name, an email subject alone, idle time or an unattended agent run leaves the duration unknown. Billing increments apply when calculating the charge after the suggested duration has been determined.
- The same source can corroborate one entry or be partitioned into separate, nonoverlapping claimed slices. The model cannot spend the same slice twice. Source corrections and accepted or dismissed proposals keep their private identities across regeneration.

## Can a normal app recover yesterday’s desktop activity?

The platform documentation supports a narrower answer than a universal accessibility-history permission. Both operating systems expose current foreground or accessibility events to an observing application. Some existing histories are available under specific conditions. None of the documented interfaces below guarantees yesterday’s sequence of matters, documents and human minutes. This review used published API documentation and synthetic LegalWork observations. It did not inspect a person’s device logs.

The desktop Day timeline action **Run suggestions → Check a folder for file activity** checks up to 500 entries and accepts up to 200 document candidates per selection. It skips hidden names, unsupported document types, nested folders and links outside the selection. The private day log receives only the document basename, source, selected day and observed use time. In a native macOS check, opening a generated text file through Launch Services supplied one real current-day Spotlight timestamp. The Windows adapter was tested with synthetic Shell responses on macOS. Shell recent lists are optional, can be cleared and may have no visit timestamp. [Apple last-used metadata](https://developer.apple.com/documentation/coreservices/kmditemlastuseddate) · [Windows Recent documents](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shaddtorecentdocs) · [Windows last visit](https://learn.microsoft.com/en-us/windows/win32/properties/props-system-link-datevisited)

### macOS

| Facility | What a desktop app can use and what consent changes |
| --- | --- |
| App activation and Accessibility | AppKit posts app-activation notifications to registered listeners. A trusted Accessibility client can register callbacks for supported notifications from a running app. Granting Accessibility permission allows those live observations. These interfaces supply no retrospective focus or interaction timeline. [App activation](https://developer.apple.com/documentation/appkit/nsworkspace/didactivateapplicationnotification) · [Accessibility observer](https://developer.apple.com/documentation/applicationservices/1460133-axobservercreate) · [Accessibility trust prompt](https://developer.apple.com/documentation/applicationservices/1459186-axisprocesstrustedwithoptions) |
| Screen Time | With App & Website Activity enabled, the user can view app usage by day or week, including per-device statistics. Apple documents a family-authorized, sandboxed Device Activity report extension for iOS, iPadOS and Mac Catalyst. Its report data cannot be exported outside the extension. These controls do not give an ordinary macOS Electron app document-level usage history. [Mac Screen Time usage](https://support.apple.com/en-au/guide/mac-help/mchlf2c0c770/mac) · [Device Activity report and platform availability](https://developer.apple.com/documentation/deviceactivity/deviceactivityreport.md) |
| Recent documents | An AppKit document controller can return recent document URLs for its own app. A recent-document entry can identify a file the user opened. It supplies no work duration. [AppKit recent documents](https://developer.apple.com/documentation/appkit/nsdocumentcontroller/recentdocumenturls) |
| Diagnostic and file histories | The system-wide unified logging store requires an admin account and Apple’s local-store entitlement. Its records depend on what components logged. FSEvents can identify changes in a permitted directory hierarchy since an earlier marker and can coalesce events. A change can come from a user, autosave or another process. Full Disk Access expands file access. It cannot supply missing events or establish how long a person worked. [Local unified log access](https://developer.apple.com/documentation/oslog/oslogstore/local%28%29.md) · [File change history](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/) · [Coalesced events](https://developer.apple.com/library/archive/documentation/Darwin/Conceptual/FSEvents_ProgGuide/UsingtheFSEventsFramework/UsingtheFSEventsFramework.html) · [Full Disk Access](https://support.apple.com/en-us/149699) |

### Windows

| Facility | What a desktop app can use and what consent changes |
| --- | --- |
| Foreground window and UI Automation | Win32 can identify the current foreground window. UI Automation can subscribe to future focus and other provider events. Some applications omit events. Standard clients have limited access to elevated and protected user interfaces. The public APIs expose no retrospective UI Automation transcript. [Foreground window](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getforegroundwindow) · [Event subscriptions](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-eventsforclients) · [Access limits](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-securityoverview) |
| Windows activity history | The user can enable and clear local history. Apps can explicitly publish resumable activities to their own application channel. Microsoft retired the Timeline interface on Windows 11 and retired cloud synchronization. These records cannot reliably establish every document, foreground application or duration across the device. [Activity history settings](https://support.microsoft.com/en-us/windows/privacy/windows-activity-history-and-your-privacy) · [Application activities](https://learn.microsoft.com/en-us/windows/apps/develop/launch/user-activities) · [Timeline availability](https://support.microsoft.com/en-us/windows/ai/ai-features/get-help-with-timeline) |
| Recent files and Jump Lists | The Windows Shell can expose existing recent or frequent document destinations for an app, including files selected through Explorer and the common file dialog. Coverage depends on how the app opens files and what the Shell retained. A recent shortcut supplies a lead to a document and cannot establish how long it was edited. [Jump List retrieval](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-iapplicationdocumentlists) · [What contributes to recents](https://learn.microsoft.com/en-us/windows/win32/api/shlobj_core/nf-shlobj_core-shaddtorecentdocs) |
| Security and file system journals | Process creation event 4688 is available where process creation auditing was enabled and log access permits reading. It establishes that a process started. Command lines require separate policy. NTFS change journals track file changes subject to volume access and retained records. Neither establishes human focus or billable minutes, and later permission cannot recreate missing records. [Process creation auditing](https://learn.microsoft.com/en-us/windows/security/threat-protection/auditing/audit-process-creation) · [Event 4688](https://learn.microsoft.com/windows/security/threat-protection/auditing/event-4688) · [File system change journals](https://learn.microsoft.com/windows/win32/fileio/change-journals) |
| Recall | On supported Copilot+ PCs, an opted-in user may have encrypted snapshots from earlier activity. Windows Hello protects access. In the EEA, the user can explicitly export past snapshots or opt into a continuing export and share the folder and export code with an application. An ordinary app receives no automatic access. If Recall was disabled, paused, filtered, or its snapshots were deleted, those missing periods cannot be recovered through this export. This is a genuine optional historical source on eligible devices. It contains screenshots and associated metadata. LegalWork does not import it. [Recall privacy](https://support.microsoft.com/en-us/windows/privacy/privacy-and-control-over-your-recall-experience) · [User-initiated EEA export](https://support.microsoft.com/en-us/windows/ai/ai-features/export-recall-snapshots) |

The desktop source starts with an explicit opt-in and two recent, matching samples. It omits browser addresses, full paths, window titles, screenshots, keystrokes and document contents. A document basename is admitted only with granted permission. On systems that report the foreground application without accessibility permission, the app name alone can supply a sampled interval. Inference removes any overlapping LegalWork foreground time from that same device while preserving an independent meeting or stopwatch. Turning off the source excludes its records from future suggestions. Previously accepted billing records remain available. Collection starts when LegalWork is running. It cannot reconstruct an earlier unattended desktop session.
