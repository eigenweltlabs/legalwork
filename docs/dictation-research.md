# LegalWork Recorder: Competitive Analysis & Feature Roadmap — Local Audio / Dictation Stack

*Research date: 2026-07-11. Primary sources: OpenWhispr repo + issues (via `gh api`), Whispering/Handy/Vibe source code, vendor sites/docs. All effort estimates are relative to LegalWork's existing Electron 35 + sherpa-onnx-node + Swift-helper stack.*

## 1. OpenWhispr Teardown

**Repo:** [github.com/OpenWhispr/openwhispr](https://github.com/OpenWhispr/openwhispr) — MIT (confirmed in `LICENSE` + `package.json`), 4,440★, 618 forks, created June 2025, v1.7.5 (2026-07-10), by Gizmo Labs Inc. Positioning: "the open-source and free alternative to WisprFlow and Granola." Business model: MIT core + paid cloud (Free: unlimited local, 2k words/wk cloud; Pro $6.67/mo: unlimited cloud, sync, API, MCP; Business $16.67/mo: unlimited meetings, diarization labels, agent mode; Enterprise: SSO/SAML/SCIM, audit logs) — [openwhispr.com/pricing](https://openwhispr.com/pricing).

### 1.1 Architecture

- **Shell:** Electron 41 + React 19 + TypeScript + Tailwind v4 + shadcn/Radix, zustand, better-sqlite3 + kysely, i18next (10 locales incl. DE), electron-updater. Secrets: AES-256-GCM with master key in OS keychain via `@napi-rs/keyring` (Keychain/Credential Manager/libsecret), migrated off Electron `safeStorage`.
- **STT — sidecar-process pattern (not N-API):**
  - **whisper.cpp** via a bundled `whisper-server` HTTP binary (own frozen fork, ports 8178–8199, health-check loop, auto-tuned threads, Silero VAD flags `--vad` + bundled `ggml-silero-v5.1.2.bin`).
  - **NVIDIA Parakeet** via a bundled `sherpa-onnx-ws` **WebSocket server binary** (ports 6006–6029). Note: this design cost them a Windows firewall prompt because the server binds all interfaces ([#1090](https://github.com/OpenWhispr/openwhispr/issues/1090)) — LegalWork's `sherpa-onnx-node` N-API-in-utilityProcess approach is strictly better here (no sockets, no firewall).
  - **Cloud/BYOK:** OpenAI (incl. Realtime GA streaming), Groq, Deepgram, AssemblyAI, Mistral, Azure AI Foundry, xAI, Tinfoil (confidential compute), self-hosted OpenAI-compatible, plus their own metered cloud. Streaming exists **only on cloud** engines; local streaming is still an open ask ([#1131](https://github.com/OpenWhispr/openwhispr/issues/1131) tracks Nemotron streaming models).
- **LLM post-processing:** local llama.cpp `llama-server` sidecar or Vercel AI SDK providers (Anthropic/OpenAI/Gemini/Groq/Bedrock/Azure/Vertex/OpenRouter). Per-scope model config (dictation cleanup vs. voice agent vs. note formatting vs. chat), with a painful per-provider "thinking suppression" compatibility matrix (Qwen `<think>` starvation, Groq rejecting unknown fields — CHANGELOG 1.7.1).
- **Diarization (fully local):** sherpa-onnx **pyannote-segmentation-3.0** + **3D-Speaker CAM++** speaker embeddings + Silero VAD ([scripts/download-diarization-models.js](https://github.com/OpenWhispr/openwhispr/blob/main/scripts/download-diarization-models.js)), running in an `onnxruntime-node` worker, with cross-meeting voice fingerprinting; embedded **Qdrant** + MiniLM for semantic note search.
- **Native helper zoo (~14 tiny binaries, all MIT):** `macos-globe-listener.swift` (hotkeys), `macos-fast-paste.swift` (injection), `macos-text-monitor.swift` (auto-learn), `macos-audio-tap.swift` (CoreAudio process tap — same approach as LegalWork's helper), `macos-mic-listener`, `macos-media-remote`; `windows-key-listener.c`, `windows-fast-paste.c`, `windows-mic-listener.c`, `windows-system-audio-helper.c` (WASAPI process loopback); Linux equivalents + a WebRTC-based `meeting-aec-helper` (echo cancellation, C++).

### 1.2 Dictation pipeline (hotkey → text at cursor)

1. **Hotkey layer** ([hotkeyManager.js](https://github.com/OpenWhispr/openwhispr/blob/main/src/helpers/hotkeyManager.js)): Electron `globalShortcut` for normal chords; **native listeners for everything Electron can't do** — the Swift globe-listener (`NSEvent.addGlobalMonitorForEvents` + a CGEventTap for mouse buttons 4/5) emits `FN_DOWN/FN_UP`, right-side-modifier and modifier-release events over stdout; on Windows a `WH_KEYBOARD_LL` low-level hook binary provides **key-up (push-to-talk) and modifier-only combos**. Defaults: **Globe/Fn on macOS, Ctrl+Win on Windows/Linux**. Fallback registration chain `F8 → F9 → Ctrl+Shift+Space`; multiple hotkeys per slot ([#1017](https://github.com/OpenWhispr/openwhispr/pull/1017)); separate slots for dictation / voice-agent / meeting / cancel. Activation is **tap-to-toggle or hold (push-to-talk)** per user setting.
2. **Recording** in a tiny always-on-top, **non-focusable**, transparent 96×96 overlay window (`type: "panel"` on macOS, `focusable:false`, `visibleOnAllWorkspaces`, skipTaskbar — [windowConfig.js](https://github.com/OpenWhispr/openwhispr/blob/main/src/helpers/windowConfig.js)) that renders the mic orb, is draggable, and hosts `MediaRecorder`.
3. **Transcribe** (local sidecar or cloud) → optional **cleanup pass** (LLM removes fillers, applies the custom dictionary substitutions, expands spoken **snippets** [#934], detects "Hey \<AgentName\>" to route to the agent instead), **smart spacing** by reading the character before the cursor via AX (`AXSelectedTextRange`).
4. **Inject** (below), then **auto-learn**: [textEditMonitor.js](https://github.com/OpenWhispr/openwhispr/blob/main/src/helpers/textEditMonitor.js) re-reads the target field via Accessibility (macOS AX / Windows UIA `ValuePattern`→`TextPattern` fallback), diffs the user's manual edits against what was pasted (Levenshtein, [correctionLearner.js](https://github.com/OpenWhispr/openwhispr/blob/main/src/utils/correctionLearner.js)) and adds corrections to the dictionary automatically.

### 1.3 Injection mechanics (the exact answer)

**It is clipboard-swap + simulated paste keystroke on every platform.** No character-typing, no AX insertion, no robotjs/nut.js.

- **macOS:** save clipboard → `clipboard.writeText(transcript)` → wait 120 ms (15 ms in streaming mode) → spawn **`macos-fast-paste`**, a 17-line Swift binary: `AXIsProcessTrusted()` gate (exit 2 if untrusted) then `CGEvent(virtualKey: 0x09 /*V*/, keyDown)` with `.maskCommand` posted to `.cgSessionEventTap`, 8 ms between down/up ([source](https://github.com/OpenWhispr/openwhispr/blob/main/resources/macos-fast-paste.swift)). Fallback: `osascript -e 'tell application "System Events" to key code 9 using command down'`. Restore clipboard after **450 ms**, guarded: skip restore if clipboard changed meanwhile; preserve rich formats on restore ([#1020](https://github.com/OpenWhispr/openwhispr/pull/1020)). All pastes serialized through a promise queue.
- **Windows:** **`windows-fast-paste.exe`** ([source](https://github.com/OpenWhispr/openwhispr/blob/main/resources/windows-fast-paste.c)): `SendInput` Ctrl+V — but first it **releases any modifier keys the user is still physically holding from the hotkey** (via `GetAsyncKeyState`) and re-presses them after; it detects terminals by window class (`CASCADIA_HOSTING_WINDOW_CLASS`, mintty, PuTTY, kitty…) *and* by exe name for Electron terminals (Termius/Tabby/Wave share `Chrome_WidgetWin_1`) and sends **Ctrl+Shift+V** there. Fallbacks: NirCmd `sendkeypress` → PowerShell `SendKeys`. Restore after 500 ms.
- **Linux:** a whole ladder — `wl-copy`/`xclip`/`xsel` clipboard writes, `xdotool`/`wtype`/`ydotool` keystrokes, KDE KWin scripting, AT-SPI2 + `/proc/<pid>/comm` terminal detection, Konsole special-cased to `Shift+Insert`. Still broken on GNOME Wayland ([#956](https://github.com/OpenWhispr/openwhispr/issues/956) — Mutter drops uinput events).
- **Permissions:** Microphone + **Accessibility** (for both the paste CGEvent and the NSEvent global hotkey monitor) + Screen Recording (meetings only). Their docs state Input Monitoring is *not* required ([docs.openwhispr.com/platform/macos](https://docs.openwhispr.com/platform/macos)). No Accessibility → degrade to "copied to clipboard, paste manually."

### 1.4 Onboarding & model UX

Eight-step wizard ([OnboardingFlow.tsx](https://github.com/OpenWhispr/openwhispr/blob/main/src/components/OnboardingFlow.tsx)): welcome → **use-case selection** (they route healthcare users to a HIPAA/EU provider — vertical-aware onboarding) → processing method (their cloud / BYOK / **local model with in-wizard download**) → permissions (cards with live status + deep links) → **activation** (hotkey capture widget + tap-vs-hold selector + "try it now" test) → voice-agent naming → meeting setup → finish. Steps are skippable; hotkey registration failure suggests alternates. Model downloads: proxy-aware, resumable, redirect-following, retry-with-backoff (each of these was a shipped bug first).

### 1.5 Their top 10 learnings/mistakes (with receipts)

1. **Don't depend on a system Python/runtime.** v1.0 ran Whisper via Python and even auto-installed Python (CHANGELOG 1.0.2) → an avalanche of `spawn python ENOENT`/install failures ([#29](https://github.com/OpenWhispr/openwhispr/issues/29), [#12](https://github.com/OpenWhispr/openwhispr/issues/12), [#102](https://github.com/OpenWhispr/openwhispr/issues/102), [#104](https://github.com/OpenWhispr/openwhispr/issues/104)). They rebuilt on bundled whisper.cpp/sherpa binaries — and then learned to **pin sidecar ABI** (llama.cpp pinned to b8857 after a ggml ABI bump silently broke `whisper-server`, CHANGELOG 1.7.1). *LegalWork already avoided this whole class with sherpa-onnx-node.*
2. **Clipboard-restore delay is a product tradeoff, not a constant.** Raising 450 ms → 2000 ms to fix one race caused a "pastes twice / my copied link is gone" regression ([#1023](https://github.com/OpenWhispr/openwhispr/issues/1023), fixed in [#1038](https://github.com/OpenWhispr/openwhispr/pull/1038)); restores must be format-preserving ([#1020](https://github.com/OpenWhispr/openwhispr/pull/1020)), skipped if the clipboard changed, and serialized across overlapping dictations.
3. **Terminals and Electron apps need a paste matrix.** Ctrl+V vs Ctrl+Shift+V vs Shift+Insert; Electron terminals are invisible to window-class checks; **Claude Code/codex-cli interpret Ctrl+V as image-paste** ([#184](https://github.com/OpenWhispr/openwhispr/issues/184), [#224](https://github.com/OpenWhispr/openwhispr/issues/224), [#1092](https://github.com/OpenWhispr/openwhispr/issues/1092), Konsole root-cause in CHANGELOG 1.7.1).
4. **macOS Accessibility grants go stale after updates/reinstalls.** `AXIsProcessTrusted()` can read true while events are silently dropped; users loop in onboarding ([#394](https://github.com/OpenWhispr/openwhispr/issues/394), [#568](https://github.com/OpenWhispr/openwhispr/issues/568)); official fix is "remove & re-add in the Accessibility list." (Whispering independently built a tap-liveness oracle for exactly this — see §3.)
5. **Windows `SendInput` fails silently.** Long transcripts (>~200 chars) reported success but never arrived ([#829](https://github.com/OpenWhispr/openwhispr/issues/829)); UIPI makes injection into elevated apps a silent no-op. Verify delivery; never trust the return code.
6. **Hotkeys are a subsystem, not a feature.** Electron `globalShortcut` can't do key-up, bare modifiers, or Fn — hence three native listeners; Fn-chord false triggers ([#1046](https://github.com/OpenWhispr/openwhispr/issues/1046), [#954](https://github.com/OpenWhispr/openwhispr/pull/954)); modifier-only combos on Windows need the LL hook ([#1001](https://github.com/OpenWhispr/openwhispr/pull/1001)); a D-Bus library swap broke tray + hotkeys for all GNOME Wayland users in a patch release ([#1100](https://github.com/OpenWhispr/openwhispr/issues/1100), [#1107](https://github.com/OpenWhispr/openwhispr/issues/1107)).
7. **Latency is the #1 perceived-quality metric.** 41 s for 6.6 s of audio on CPU ([#989](https://github.com/OpenWhispr/openwhispr/issues/989)), 12–16 s on small models + language auto-detect overhead ([#1055](https://github.com/OpenWhispr/openwhispr/issues/1055)); mitigations shipped: thread auto-tune ([#994](https://github.com/OpenWhispr/openwhispr/pull/994)), keep-model-in-VRAM ([#766](https://github.com/OpenWhispr/openwhispr/issues/766)), reload-on-wake ([#1032](https://github.com/OpenWhispr/openwhispr/pull/1032)), pre-warm. Users persistently ask for **streaming text at the cursor** ([#296](https://github.com/OpenWhispr/openwhispr/issues/296), [#696](https://github.com/OpenWhispr/openwhispr/issues/696), [#217](https://github.com/OpenWhispr/openwhispr/issues/217)).
8. **Silence handling: Whisper hallucinates** ("Thank you for watching!") without VAD ([#462](https://github.com/OpenWhispr/openwhispr/issues/462)) → Silero VAD end-to-end; but the VAD model was then missing from the Windows installer, silently disabling it ([#1062](https://github.com/OpenWhispr/openwhispr/issues/1062)) — bundle-verification CI matters.
9. **Identity/signing/updates are trust-critical.** Bundle-ID migration broke the auto-update chain for all 1.6.x users (CHANGELOG 1.7.0); AV false-positive reports ([#1096](https://github.com/OpenWhispr/openwhispr/issues/1096)); updater crashes ([#1012](https://github.com/OpenWhispr/openwhispr/issues/1012), [#1006](https://github.com/OpenWhispr/openwhispr/issues/1006), [#1108](https://github.com/OpenWhispr/openwhispr/issues/1108)); three spurious Keychain prompts on first launch fixed by deferring keychain access (CHANGELOG 1.7.2). *Matches LegalWork's own ad-hoc→Developer-ID bridge learnings.*
10. **Never degrade silently.** A stack of issues about invisible failure: cleanup-LLM failures pasting raw text with no error ([#1003](https://github.com/OpenWhispr/openwhispr/issues/1003)), cloud-only mode silently degrading ([#1082](https://github.com/OpenWhispr/openwhispr/issues/1082)), cleanup **answering the user's dictated question instead of transcribing it** ([#1066](https://github.com/OpenWhispr/openwhispr/issues/1066), [#1054](https://github.com/OpenWhispr/openwhispr/pull/1054)), empty cleanup wiping the transcript ([#938](https://github.com/OpenWhispr/openwhispr/issues/938)), and preserving even *discarded* dictations in history because "text I spoke vanished" is the worst failure ([#964](https://github.com/OpenWhispr/openwhispr/pull/964)).

Bonus lesson for our auto-learn plans: **never write `AXEnhancedUserInterface`** on target apps to force their AX tree — it switches Chromium apps into screen-reader mode for their lifetime and breaks focus; read-only monitoring only ([#1116](https://github.com/OpenWhispr/openwhispr/pull/1116)).

**License/reuse:** MIT confirmed — we may lift code outright with attribution: the Swift/C native helpers (fast-paste, globe-listener, key-listener, text-monitor), `clipboard.js` delay/queue/restore logic, hotkey slot manager, correction-learner, diarization model plumbing. Their brand assets and cloud backend obviously excluded.

## 3. Platform mechanics (what the OSS apps actually chose)

Condensed reference for the roadmap spec; full sourcing inline.

- **Hotkeys without permissions:** macOS Carbon `RegisterEventHotKey` delivers **both press and release** for chords with *zero* TCC permission; Windows `RegisterHotKey` + `GetAsyncKeyState` polling gives release. This is what Tauri's [global-hotkey](https://github.com/tauri-apps/global-hotkey) does — Electron's `globalShortcut` uses the same OS facilities but **doesn't surface key-up** ([electron#7802](https://github.com/electron/electron/issues/7802)) and rejects modifier-only/Fn accelerators ([electron#21518](https://github.com/electron/electron/issues/21518)). So: a ~100-line native helper (or `uiohook-napi`) is required for hold-to-talk UX in Electron; OpenWhispr's MIT helpers are exactly that.
- **macOS TCC matrix:** posting events (CGEventPost paste) → **Accessibility** (`CGPreflightPostEventAccess`/`CGRequestPostEventAccess`); `NSEvent.addGlobalMonitorForEvents` for keys → **Accessibility** ([Apple docs](https://developer.apple.com/documentation/appkit/nsevent/addglobalmonitorforevents(matching:handler:))); *listen-only* CGEventTaps → **Input Monitoring**; active taps → Accessibility. OpenWhispr's combo (NSEvent monitor + CGEventPost) needs Accessibility only — the right choice.
- **Stale-grant trap:** after an update changes the signature, `AXIsProcessTrusted()` can return true while posted events are dropped. Whispering's fix ([ADR-0117](https://github.com/epicenter-so/epicenter/blob/main/docs/adr/0117-global-shortcut-input-is-plugin-chords-only-and-the-macos-tap-is-just-the-paste-grant-watcher.md), [`mac_tap.rs`](https://github.com/epicenter-so/epicenter/blob/main/apps/epicenter/src-tauri/src/keyboard/mac_tap.rs)): keep a passive tap alive purely as a **grant-liveness oracle**; a dying tap under a "trusted" grant ⇒ tell the user to remove & re-add the app. Whispering also *deleted* their raw-keyboard listener and now refuse bare-Fn/modifier-only bindings as a product decision — a cautionary counterpoint to OpenWhispr's helper zoo.
- **Secure input:** password fields call `EnableSecureEventInput` ([TN2150](https://developer.apple.com/library/archive/technotes/tn2150/_index.html)) — taps/monitors go deaf system-wide, and a stuck holder (browser, password manager) breaks hotkeys everywhere. Detect via `IsSecureEventInputEnabled()`, identify the culprit PID via IORegistry `IOConsoleUsers`/`kCGSSessionSecureInputPID` the way [espanso does](https://github.com/espanso/espanso/blob/master/espanso-mac-utils/src/native.mm), and *tell the user* instead of failing silently.
- **Clipboard-swap hazards:** text-only save/restore destroys copied images/files — Whispering snapshots **every `NSPasteboardItem` UTI byte-for-byte** and skips promised/lazy data ([delivery.rs](https://github.com/epicenter-so/epicenter/blob/main/apps/epicenter/src-tauri/src/delivery.rs)); it also marks the transient write with `org.nspasteboard.ConcealedType` ([nspasteboard.org](http://nspasteboard.org)) so clipboard managers don't record the dictation. Timing: 50 ms pre-paste / 100–500 ms pre-restore is the observed working band.
- **Windows:** `SendInput` is UIPI-gated — injection into elevated windows silently no-ops with no error ([MS docs](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)); `uiAccess=true` bypass requires CA-signed binaries in `%ProgramFiles%` (not worth it — detect foreground elevation and toast instead). `WH_KEYBOARD_LL` hooks need no permission but are silently removed if the callback exceeds ~1000 ms ([LowLevelKeyboardProc](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelkeyboardproc)); the UAC secure desktop swallows key-ups (Handy ships drift-correction for phantom stuck keys — [handy-keys](https://github.com/handy-computer/handy-keys)).
- **Typing vs pasting:** char-typing (`CGEventKeyboardSetUnicodeString` 20-unit chunks / `KEYEVENTF_UNICODE`) leaves the clipboard untouched but is slow, produces fragmented undo, and Apple documents that frameworks may ignore the unicode payload. Every serious app defaults to clipboard-paste with typing as opt-in (Handy) or not at all (Whispering, OpenWhispr).
- **Local streaming ASR unlock (June 2026):** NVIDIA **Nemotron-3.5 ASR streaming 0.6B** — cache-aware FastConformer-RNNT, **40 language-locales incl. German**, punctuation + capitalization, low-latency chunks — is now supported in sherpa-onnx master ([HF model](https://huggingface.co/nvidia/nemotron-3.5-asr-streaming-0.6b), [sherpa-onnx#3664](https://github.com/k2-fsa/sherpa-onnx/issues/3664)). This gives LegalWork *true* streaming local dictation on the runtime we already ship — ahead of OpenWhispr, which still only streams via cloud.

## 5. Roadmap Proposal

### Phase 1 — "Dictate anywhere" (headline: system-wide dictation, macOS + Windows)

**Product framing:** an **opt-in system setting** — Settings → Recorder → *System-wide dictation (Beta)*. Off by default; enabling walks through a dedicated permission mini-flow. Fully on-device, DE/EN, works in every app.

**Concrete spec for our Electron 35 + sherpa-onnx-node stack:**

1. **Hotkey layer** (new `apps/desktop/electron/dictation/hotkeys.mjs`):
   - Chords via Electron `globalShortcut` (press-only, toggle mode), with OpenWhispr's fallback-suggestion pattern on registration failure.
   - Hold/push-to-talk + Fn/right-modifier support via two tiny native helpers, ported from OpenWhispr (MIT): **macOS** `globe-listener` Swift binary (NSEvent global monitor, stdout events `FN_DOWN/FN_UP`… — we already build/sign Swift helpers for the CoreAudio tap, so toolchain + notarization pipeline exist); **Windows** `key-listener.exe` (`WH_KEYBOARD_LL`, key-up + modifier-only combos; callback <1 ms, drift-correct stuck keys after UAC secure desktop).
   - Defaults: macOS **hold Fn** (tap = toggle), Windows **Ctrl+Win**. Both remappable; capture widget with conflict detection; Esc = cancel slot registered only while recording (Handy's pattern).
2. **Capture + ASR:** reuse `recorder-service.mjs` mic path → existing Silero VAD + sherpa-onnx utilityProcess. PTT release ⇒ single offline decode (Parakeet v3 for DE/EN speed, Whisper turbo as quality option — both already in our catalog); toggle mode ⇒ our existing ~1.5 s partial loop feeds the HUD. Keep engine pre-warmed while the setting is on; re-warm on wake (OpenWhispr #1032).
3. **Injection engine** (new `dictation/inject.mjs`, port of OpenWhispr `clipboard.js` logic, hardened with Whispering's findings):
   - **macOS:** full-fidelity clipboard snapshot (all pasteboard items/UTIs, skip promised data — via a small Swift helper method; *not* Electron's text-only API) → write transcript + `org.nspasteboard.ConcealedType` → 120 ms → spawn `fast-paste` Swift helper (CGEvent Cmd+V, AXIsProcessTrusted gate, exit-code contract) → osascript fallback → restore after 450 ms with changed-clipboard guard; serialize pastes.
   - **Windows:** `fast-paste.exe` port — SendInput Ctrl+V, release+restore held modifiers, terminal detection (window class + exe name; include Windows Terminal, VS Code terminal, Claude/codex CLI hosts → Ctrl+Shift+V); verify delivery for long texts (#829: chunk >200-char pastes or verify via UIA), detect elevated foreground process ⇒ toast "can't dictate into an admin window."
   - **Universal fallback:** if paste can't be posted (no Accessibility, secure input, elevated target) ⇒ leave on clipboard + HUD toast "Copied — press ⌘V" (never silent).
4. **Permissions flow** (extends our guided capture-permission flow): macOS needs **Accessibility only** (mic already granted). Wizard: explain → `AXIsProcessTrustedWithOptions` prompt → deep-link `x-apple.systempreferences:...Privacy_Accessibility` → poll until granted → **live self-test** (post a probe event / run the fast-paste helper against a hidden test field) to catch the stale-grant trap; on failure show the "remove & re-add LegalWork" fix (OpenWhispr #394, Whispering ADR-0117). Windows: no permission needed; check mic ConsentStore registry, deep-link `ms-settings:privacy-microphone` if denied.
5. **Tray + mini-HUD:** add a Tray icon (start/stop dictation, open recorder, stealth toggle, quit). HUD = small frameless `panel`-type window: non-focusable (critical — must never steal focus from the target field), `visibleOnAllWorkspaces`, screen-saver level, `setContentProtection(true)` always (consistent with stealth mode — the HUD never appears in screen shares); shows state (listening/transcribing), live partial text, language badge, cancel button, "recording locally" red badge reuse.
6. **Settings surface:** master toggle; hotkey + activation mode (tap/hold); paste method (auto / clipboard-only); insert language (EN/DE/auto); model picker (shared catalog); "restore clipboard" toggle; per-app disable list (v1: manual bundle-id/exe list); history toggle ("save dictations to recorder history" — with the #964 lesson: default on, and even canceled dictations recoverable for 24 h).
7. **Honest-failure layer:** secure-input detector on macOS (`IsSecureEventInputEnabled` + culprit PID à la espanso) surfaces "Dictation paused — a password field or app X has secure input"; every degradation gets a HUD toast.

*Also in Phase 1:* #2 (activation modes — inherent), #10 (tray/HUD — inherent), #11 (honest failures), #14 (sound feedback), #15 (bundle CI).

### Phase 2 — "Legal dictation quality"

- #4 matter-aware vocabulary: dictionary + replacements UI, sherpa-onnx hotword boosting seeded from the active workspace (parties, defined terms, file names); German legal seed lexicon.
- #3 cleanup modes: 4–6 shipped legal modes (DE+EN) + custom prompts; per-app auto-mode (frontmost-app detection we already need for injection); routed through local LLM or firm model — never silently, always with raw-transcript fallback (#938, #1003 lessons).
- #5 auto-learn corrections (read-only AX/UIA monitor) feeding the dictionary — and logged as **expert-correction data for firm-model fine-tuning** (the Eigenwelt compounding loop).
- #8 undo-last-dictation hotkey; then edit-last-by-voice.
- #9 streaming: integrate Nemotron-3.5 streaming (EN+DE) behind the existing partials UI; defer streaming-*paste* (replace-as-you-speak in foreign apps is the hardest UX in the field — OpenWhispr hasn't shipped it either).

### Phase 3 — "Ambient matter capture"

- #6 local diarization + voice fingerprints on the recorder + meeting transcripts (sherpa-onnx models we already run).
- #7 meeting detection (process detector + optional calendar) with consent-first prompts (recording-consent law varies — DE §201 StGB — so explicit, logged consent UX is itself a legal-vertical feature).
- #12 global voice-agent hotkey (dictate commands to the opencode agent from anywhere; results via HUD).
- AEC helper for meeting mic hygiene (OpenWhispr's WebRTC-based `meeting-aec-helper`, MIT) if diarization quality demands it.
- Firm-level admin: org policy for dictation defaults/blocklists (mirrors OpenWhispr #1074 enterprise direction).

**Sequencing rationale:** Phase 1 turns an in-app recorder into a daily-use system utility (the retention driver every competitor proves); Phase 2 is where LegalWork stops being "OpenWhispr for lawyers" and becomes matter-aware (vocabulary/modes/corrections nobody horizontal can copy); Phase 3 converts the same stack into ambient documentation. The single biggest de-risking fact from this research: every hard problem in Phase 1 has MIT-licensed, battle-tested reference code (OpenWhispr helpers + Handy) and a documented failure catalog (issues cited above) we can design around on day one, while our sherpa-onnx-node/utilityProcess runtime is already architecturally ahead of OpenWhispr's sidecar-server approach.
