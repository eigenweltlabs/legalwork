# Legacy history: visible consequences of upstream conversion

This is a read-only source audit against frozen dev `4cd058941a96752ce7aca97ea71c97341f56a84b`, the migration worktree, and [released upstream conversion](https://github.com/anomalyco/opencode/blob/v2.1.4/packages/core/src/database/v1-migration.bun.ts). It separates observable feature losses from arbitrary metadata that LegalWork does not currently consume. The approved preservation uses one native engine and a private read-only original snapshot; it does not run a second engine or maintain a parallel mutable transcript.

The actual released-engine fixture proves ordinary user/assistant prose, full completed-tool output and metadata, token/cache/reasoning fields, cost and inline file bytes survive. Synthetic reminder text survives as native model-visible context; the renderer hides native synthetic messages without depending on old metadata flags. Deliberately malformed records are reported and skipped. The fixture seeds synthetic records offline into a real v1 schema and runs real v2 conversion; it does not claim inference or production-data coverage.

| Legacy information | Current visible consumer | Migration consequence and evidence |
| --- | --- | --- |
| User text-part `legalworkScheduledTask` | `scheduled-message.ts` and `ScheduledTaskRunCard` | The direct task/workspace identity is omitted. The existing `[Scheduled task: title]` text envelope still renders the card with its title and prompt. Its Open action can recover only if the current task title/prompt match uniquely and its run list confirms this chat. A renamed task, duplicate task or expired run membership can lose that direct historical link. |
| Arbitrary message metadata | No other app-specific writer/visible consumer found in the frozen ordinary message path | Upstream omits it, but this audit cannot call unused arbitrary fields a proven current UI regression. External plugins may have their own consumers. |
| Completed-tool `state.metadata` | View previews, subagent links, skill display, Office state reminders and other tool cards | Upstream preserves it; the actual fixture checks Office reminder state and custom revision metadata. This information should not be described as lost message metadata. Tool output already cleared by old compaction is not recoverable as full output from that old record. |
| Assistant text/reasoning part metadata | Provider-native fields; no app-specific historical card consumer found | Upstream moves it to native `content.native`. This is relocation, not deletion from the raw native history. |
| Session metadata | Review worker visibility and other session properties | Separate from message metadata; upstream copies session metadata. Review-worker filtering is not inherently lost through the omitted user text fields. |
| User non-inline file part (`file://`, remote URI) | File badges, source/open-target resolution and model attachment context | Upstream replaces it with an unavailable-file text notice. The real fixture proves the badge/file entry is absent. The workspace file may still exist in Project Files, but its current bytes are not guaranteed historical bytes. |
| Inline file origin (`source.type=file` / symbol) | Exact original-file navigation | Inline bytes/MIME/name survive. Upstream replaces those origin paths with inline source and preserves mention offsets; resource URI sources survive. Filename fallback can still open a workspace file, but cannot guarantee the exact original path when names collide. The real migration fixture checks exact original path recovery from the immutable original snapshot. |
| Completed-tool file attachments | Tool result attachment cards/open targets | Upstream retains attachment URIs as native file content. They do not share the user-file data-only migration rule. The fixture verifies an inline tool attachment remains present. |
| Staged session revert/Undo cursor | Transcript tail hiding and Redo in `transcript-reconcile.ts` / `actions-store.ts` | Upstream resets it. For a chat left in staged Undo, formerly hidden tail messages can reappear and Redo state disappears. Ordinary chats with no staged revert are unaffected. The real released-engine Undo fixture now seeds chat-only, partial-message and file Undo states and checks the safe restoration boundary. |
| Persisted quota-stop reason | `session-usage-limits.ts` | Already stored separately in LegalWork's existing runtime database, keyed by workspace/session/message. It is not arbitrary engine message metadata and is projected onto native errors. |

The frozen composer uses inline data for dropped file uploads and `file://` for workspace-file chips and first-line local file paths. The non-inline limitation therefore touches a normal input path. Files themselves are not deleted by upstream history conversion.

The existing scheduled-task store contains run/session identity, which might support more precise recovery of recent historical card links without introducing another chat-history store. Its preexisting retention keeps only the latest **50 runs per task**, and deleting a task deletes its run rows. That unchanged cap prevents claiming complete historical reconstruction from those records alone.

The approved implementation freezes a consistent SQLite original before conversion in the private runtime directory (`history-v1/original.db`, owner-only directory, read-only file). Its manifest records a streaming SHA256 and source identity. Native conversion receives a separate writable inode. The original is not refreshed when source files change and survives future native cleanup of retained v1 tables. Integrity failures are explicit; they do not silently present missing provenance as a successful migration.

After authoritative native workspace/session authorization, `session-history-provenance.ts` reads only validated original user records corresponding to native message IDs and creation times. It restores the original scheduled-task identity and attachment name/path/reference in presentation metadata. Inline byte claims require exact native byte/MIME/name matching; no backup bytes are exported. Non-inline attachments are labeled **Original attachment reference**, and any link says **Open current file** because the original bytes were never saved. Ordinary current-file authorization remains in force. Native message history and future model input remain authoritative and unchanged.

The native `legalwork_history_provenance` tool exposes this full reference payload on demand with native read permission. Its caller identity comes from native execution context. The server allows only that caller or its same-project ancestors; siblings, unrelated projects and review workers are excluded. It adds no bulk backup context to every prompt and never automatically hydrates a mutable current file as a historical attachment.

`session-history-undo.ts` restores chat-only Undo only after project automation approval, with no pending native work, no partial-part/file patch/diff, and an exactly matching captured snapshot when the old state had one. A private per-session receipt records completion so a later user Redo/Commit is not undone by application restart. The real fixture verifies native staging, restart, Redo, Commit and native context removal. The released import API ignores old revert state; stage cannot import an old partial cursor or original file Redo snapshot. Those states remain explicitly unresolved, with a banner and admission block. Reads and stop remain available. The native service/recovery path must enforce the same readiness rule before resuming jobs; HTTP guarding alone cannot establish that safety.

Metadata-only inspection of the standard local LegalWork profiles found zero unfinished Undo states. This does not remove the need to detect them in other installations. There is no new transcript, tool-output, attachment-count or ancestry-depth cap. The approval notice uses a scrollable viewport, which does not discard any reviewed configuration or plugin. Zero-inference released-engine tests use explicit startup/test watchdogs (30/60 seconds); those are infrastructure limits, not agent run deadlines.
