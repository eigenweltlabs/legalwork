# Local conversation snooze

Snooze extends the existing owner-bound encrypted mail store and host client. It does not introduce provider authentication, remote mailboxes, provider-side rules or a scheduling service. It works with read-only Gmail, Graph and IMAP mirrors. Imported archives and retained integration copies are excluded.

Schema 36 adds versioned `mail_snoozes` headers and `mail_snooze_members`. Scope is computed from the current provider conversation inside one account, or the exact message identity for a singleton. A bounded snapshot includes up to 1,000 current live Inbox members, excluding spam, trash and tombstones. Only local metadata changes. Header and member changes, their local events and version increments commit in one transaction. Generation/revision checks prevent stale dialogs from clearing or extending a newer snooze, including after clear and recreation. Fixed UTC instants use the existing time-zone picker.

Inbox reads, folder Inbox reads, conversation scope matching, unread badges and notification eligibility consult the same active member predicate. All-mail reads, source reads and search retain the downloaded messages. A bounded refresh clears up to 16 due or newly active conversation scopes per read/event/badge poll. A new live Inbox member outside the snapshot wakes the group, including a later historical download or a move into Inbox. Sent-only updates and other accounts do not wake it. Moving all snapshot members out of Inbox, removing them, or changing their conversation identity ends the old local scope. Expiry never edits provider memberships or removes provider tombstones.

Wake-up records a separate local position timestamp. Received-order Inbox pages and the unified account merge use it to bring the conversation to the top while retaining original `receivedAt` values. Keyset cursors, including worker frame trimming, carry the selected ordering timestamp. All mail retains provider received order. Local event publication lets the existing polling UI refresh or show its newer-mail control without stealing focus or resetting an expanded list.

Refresh requires an open encrypted worker, not a network connection. Expired work catches up after unlock or restart; the computer is not kept awake. Notifications retain their existing opt-in, baseline and at-most-once claims. Ending a snooze cannot restore a provider-archived or deleted message to Inbox. It is a view setting on this device, not cross-device provider snooze parity.

The public surface is limited to exact account-scoped snooze read/set operations on local host-token routes. Clients submit a pinned locator, expected version and chosen time or null. Owner IDs, arbitrary scope keys, credentials and provider options are rejected. Responses are bound to the initiating account and locator. Unknown errors are redacted; fixed typed errors cover stale versions, invalid times, unavailable mail and the snapshot limit.

Headless validation covers whole-conversation suppression, Inbox folders, All mail, unread counts, notifications, due and early wake, original dates, ordering and stable pagination, provider/account identities, IMAP UID validity, transaction rollback, migration rollback and private worker lock/unlock. UI source uses shared controls and the existing time picker.

Standard-profile Mac Electron acceptance on 2 November 2026 verified a valid future snooze on a conversation with one current Inbox member. Inbox changed from five rows to four, Snoozed contained the conversation, and reopening showed the saved 07:00 Europe/Berlin time with GMT+01:00. End snooze cleared the Snoozed view and restored all five Inbox rows with the original received date. The test snooze was cleared. Earlier interactive checks cover missing/skipped/repeated wall times, Cancel/Escape and return focus. [Local rules](mail-local-rules.md) are implemented separately; successful scheduled dispatch and enabled-rule provider execution remain open under MAIL-161.
