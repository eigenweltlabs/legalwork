# EIG-139 reader correction — 12 September 2026

This change makes an actual message open queue a read mutation through the existing durable local journal. Checkbox selection and context-menu preparation do not open or mark a message. Opening a conversation expands its latest and loaded unread messages; older read messages stay collapsed. Further history loads explicitly in pages. Polls never repeat that initial opening intent, so a deliberate Mark unread remains effective until another open.

Normal lists request account-scoped provider conversations. Their count and unread count cover the full stored thread, not the current list page. A thread appears when at least one member matches the selected folder; its representative is its latest nonremoved member, including replies in Sent. Identical subjects alone do not merge. Gmail and Microsoft provider thread identifiers support grouping; IMAP/archive messages without a stored trustworthy thread identifier remain single messages. Scoped search opens the selected result without expanding unrelated thread members. Mailbox actions still target the active individual message or explicit checkbox selection, not every member implicitly.

Reader refresh preserves mounted HTML frames for unchanged content and metadata polling. It updates changed original/content state in place and distinguishes transient transport failures from authoritative unavailable/locked access. The isolated frame now requests its size at parent layout registration and child load, with source and nonce checks retained. Body and inline image preparation publish together.

Final acceptance used the shared EIG-172 production-shell preview, with one Electron instance and synthetic mail only. Twenty first opens/rapid selections, five plain/HTML boundaries, pending-to-complete content, explicit Mark unread, and 11.5 seconds of idle polling passed. The idle check preserved frame identity, srcDoc, load count, and scroll. Initial content-request HTTP 503 recovery also passed on the next successful validation, without requiring a format toggle. The [first visible body](evidence/eig-139-first-visible-body.png) and [after-idle capture](evidence/eig-139-after-idle.png) record the actual rendered reader.

Acceptance combines those successful phases with a separate targeted paging continuation after the final StrictMode fix; it does not claim that the entire earlier script completed successfully. The [pre-fix report](evidence/eig-139-before-strictmode-fix.json) retains its failed overall result: the visible-open and recovery phases passed, but the first conversation page failed. StrictMode's first aborted effect had left a shared loading boolean set, preventing the replacement initial load; a later poll populated cards without the initial expansion/cursor setup. Commit `6fa8f79b2` binds loading ownership to the request signal, so an old request cannot block or clear its replacement.

The no-launch `apps/app/tests/fixtures/mail-design/reader-pagination-regression.mjs` then passed in the same shared preview: first 25 cards loaded in 20ms, explicit history advanced to 50, remained 50 across a 5.5-second poll, advanced to 55, and remained 55 across another poll with no remaining cursor. Only the latest message was initially expanded. The [exact passing report](evidence/eig-139-pagination-pass.json) and [55-message conversation capture](evidence/eig-139-55-message-conversation.png) preserve this final phase. The visible-window runs used the same body-visibility assertions. The [recovery-probe race report](evidence/eig-139-recovery-probe-race.json) preserves a subsequent one-shot child inspection made before its document committed; the probe now waits for the bounded matching visible child, as it does on first open. No assertion was relaxed to accept clipped or absent body text. The original standalone height failure remains unexplained and is not used as passing evidence.

EIG-141 separately owns the retained-dataset query optimization and its measurement; no new ingestion or full suite was run for this reader acceptance.

No live mailbox was opened or mutated by these tests. No normal profile or provider credentials were used. All captures and reports contain synthetic data. Review correction: unread aggregation now applies the latest queued/running/dispatching/retry read intent per canonical message locator in the same account SQL snapshot as stored membership counts. It does not subtract renderer estimates from an already-refreshed count. Native regression covers two unread members, queued read, partial provider membership refresh, success, cancellation, and explicit queued unread. The conversation row dot follows that aggregate.

Authoritative removed checks remove an expanded card; removing the active card closes the reader without automatically opening or marking another message. A collapsed older page retains its downloaded header until it is reopened/refreshed; opening checks the authoritative message before loading bytes. Account/access denial still clears the reader. Transient validation notices clear after successful validation independently of genuine body/content errors. Earlier-history cursors remain independent of latest-page background refresh.
