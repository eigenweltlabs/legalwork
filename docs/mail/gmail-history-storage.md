# Durable Gmail history and reconciliation

Schema v7 adds run phase, baseline/history page checkpoint and next poll time, plus account-scoped message presence, scan generation and decimal-string message history version. Migration treats existing Gmail messages as present; old unanchored runs must begin a new reconciliation generation before enumeration. Originals, projections, drafts, actions and previous jobs remain retained.

Capture the profile baseline before any enumeration checkpoint. Apply each history page inside one outer database transaction containing journal `commitPage`, message changes and `advanceHistory` CAS. Intermediate pages preserve the baseline; only the terminal page advances it. The ongoing `gmail:history` journal scope never declares final discovery. Generation/revision, credentials and job lease fences remain the engine's responsibility at each asynchronous boundary and publication callback.

Expired history starts `beginReconciliation` with a newly captured baseline and fresh generation. Full listing uses `markSeenFromList` to observe presence while preserving the actual per-message history version; an unknown version remains null. The mailbox-wide profile anchor is never assigned to individual messages. `markMissingBatch` rejects partial enumeration and bounds each sweep to 1–500 records; `advanceHistory` rejects a transition before enumeration and sweep finish. Absence clears memberships and records a tombstone, never deletes content. Completed-scan absence preserves each message’s existing version, just like a fenced GET404; subsequent genuinely newer history events can update it. Account-wide removed and retained-original counters remain visible across generations.

History IDs use decimal strings and BigInt comparison. Older label deltas, removals and raw metadata cannot overwrite newer observations. `putGmailMetadata` returns false on stale input; engine callers must obtain a sufficiently recent full metadata snapshot and recheck inside publication before succeeding a raw job. This matters especially for a previously unknown message whose initial label baseline is missing. Unknown versions cannot overwrite known versions. `markAbsentFromFetch` is reserved for a current fenced message GET404 or completed-scan absence and preserves the existing message watermark; it must not use a later unrelated profile watermark. An explicitly reappearing message requeues a terminal raw job only when its original is absent, within the same generation; retained originals are reused.

Validation: actual encrypted Node tests cover pre-enumeration anchors, reopen/CAS, large history IDs, stale snapshot reporting, atomic page rollback, partial-scan rejection, bounded sweep, retained originals/drafts/actions, authoritative fetch absence and reappearance, and atomic v6 migration. All inputs are synthetic. No live Gmail or push-notification claim is made.
