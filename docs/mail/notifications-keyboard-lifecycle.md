# Mail notifications, keyboard access and lifecycle (EIG-147)

Settings → Mail Accounts contains desktop notification, preview, sound, and background pause controls. Notifications default off, preview defaults to no details, sound defaults off. Sender-only and sender-plus-subject are explicit choices; message bodies never enter OS notification payloads. OS permission, Focus/Do Not Disturb and notification center policy still apply. The desktop adapter owns Mail banners only; existing unread badge preference and other app notifications remain separate.

The encrypted schema 22 ledger records account-scoped event cursors and message claims. Initial discovery must finish before alerts are armed. A new app session, credential generation, event-stream generation, or notification configuration establishes a new baseline at the current event head. Only unread current Inbox arrivals with provider receive time at or after that baseline qualify. Old backfill, reflags and repeated events do not alert. Gmail uses UNREAD membership; Graph and IMAP use observed read flags. Spam/trash and revoked/locked accounts are excluded. Claiming precedes native delivery: a crash or OS delivery failure may lose an alert, but cannot replay a storm after restart. This is at-most-once notification delivery, not a guarantee that the OS displayed a banner.

Each poll scans at most 200 accounts and 1,000 events, returns at most five targets within a 48 KB payload budget, and claims excess arrivals as suppressed. The native adapter emits one grouped banner per batch and retains one active Mail banner. Clicking opens the newest target. A current account/message read is required before exposing a preview and again before navigation. Screen lock, settings changes, sleep and quit invalidate pending callbacks and close retained banners. The queued click carries the local server origin plus account ID and typed provider locator; another server connection cannot consume it. No external mail URLs are opened.

Mail keyboard controls work only while focus is inside the Mail component. `/` or the platform Find chord focuses search; C composes, R replies, Shift+R replies to all. These letter shortcuts ignore text inputs, selects, editable content, composition events and shell modifier chords. Escape clears active search. Up/Down/Home/End navigate focused message rows, and ordinary Tab/Enter retain their native button behavior. The toolbar includes a keyboard help disclosure and actions expose accessible labels and shortcut metadata.

Background pause persists in the ordinary app profile. The native controller supplies the suspended state before the encrypted worker starts, and runtime lifecycle commands serialize suspension/resumption. Sleep closes provider sessions and aborts draft synchronization; wake reinstates connected sessions without changing durable account pauses. Local reads remain available while background work is paused. The service supervisor reinstalls provider configuration after worker restart, and the renderer automatically reloads safe reads once the service is ready. Recovery does not replay failed UI mutations or erase journal uncertainty. Quitting uses the existing orderly runtime shutdown. macOS may keep the app running after the window closes; Windows follows the existing app quit/close policy. No independent system service is installed, and nothing can send while the machine is off or the app has quit.

EIG-146 uses the same lifecycle contract: outbox startup must recover durable state but remain suspended until allowed; enqueue/retry wakes must respect `lifecycleSuspended`; suspend must abort and await active work, preserving crossed-dispatch uncertainty. Outbox integration is checked with its delivery commit. There is no OS wake scheduler or machine-off scheduled sending.
