# Graph full mailbox sync (EIG-130)

The local host API now selects the connected account's provider before loading trusted OAuth settings. Existing `/mail/v1/accounts/:accountId/sync/start`, `/sync/pause`, and `/sync` routes work for Gmail and Graph. Offline message, folder/thread, part, and byte reads use the same owner/account/credential gates. Provider tokens, continuation URLs, paths and raw error responses never enter progress responses.

Graph sync discovers root and nested folders (including hidden folders), then paginates `/me/messages` without a date filter. Ordinary Archive, Junk and Deleted Items folders are part of the primary mailbox scope. Every request includes `Prefer: IdType="ImmutableId"`; message identity remains account-scoped and case-sensitive, independent of RFC Message-ID, conversationId, content hash and parentFolderId. Metadata snapshots preserve flags, categories, provider dates and changeKey. A moved immutable message changes membership while retaining its existing original. Retained MIME is bound to changeKey: changed drafts are refetched, and metadata checks around original/attachment retrieval prevent mixing known different versions. Full enumeration is not an atomic snapshot; subsequent delta reconciliation belongs to EIG-131.

Provider MIME streams into the encrypted chunked content store. The existing bounded MIME projector derives text/HTML and MIME attachments. The engine additionally enumerates Graph attachment pages and downloads every supported file/item `/$value` into the same encrypted store, including embedded Outlook items. Direct attachment references remain owned by the Graph metadata table. Identical MIME-derived bytes share the content reference; other direct attachments are exposed as `graph:<attachmentId>` parts with provider names, content types and content IDs. Direct filenames are indexed under the same account scope, and native metadata changes dirty the search index. File byte counts are checked against provider metadata. Only final projection plus the complete direct attachment inventory makes the message complete.

Cloud-reference attachments cannot be downloaded through attachment `/$value`; they remain explicit unavailable parts. No external link is fetched. Recognized S/MIME/PGP/IRM envelopes remain intact but do not claim a readable complete projection. Protected or inaccessible originals, folders and attachments yield attention and separate inaccessible counts. In-place archive mailboxes are explicitly listed in `unsupportedScopes` as `in-place-archive-mailbox`; they are different from the ordinary Archive folder and are not silently counted as synchronized. Global-cloud `/me` primary mailboxes are supported; delegated/shared mailbox enumeration, national clouds, in-place archives, Graph delta/watch, mutation and sending are outside this ticket.

Schema v9 follows the accepted search v8 migration. It adds account-bound run state, a durable folder discovery queue, provider metadata/completion state and raw-bound native attachment references. Existing drafts, actions and original blobs are untouched. Page metadata, job insertion and continuation updates commit atomically. Pause/close and credential generation changes fence publication. Interrupted pages resume their stored continuation; jobs retain lease fencing and persisted retry budgets. Exhausted or inaccessible content stays visible rather than becoming a false complete result. No automatic destructive recovery occurs for invalid/expired full-list continuations.

Resource limits: one Graph account session, one physical discovery/access operation, two jobs per executor turn, up to 100 records requested per page (500 response ceiling), 4 MiB JSON response, 64 MiB original, 32 MiB per direct attachment, 64 MiB total direct attachment bytes per message, 100 attachments per message, depth 32 for folder traversal, and at most 64 KiB writer chunks. Processing is sequential; ciphertext and metadata grow on disk with the archive. Provider Retry-After floors survive restart, including large numeric or HTTP-date values; timers wake in bounded intervals rather than overflowing. Monotonic deadlines are checked after awaits and before delivering bytes. Ignored cancellation retains the pending physical slot until settlement; worker termination releases it. A whole MIME original or decoded attachment is never accumulated by the transport/content writer; the MIME projector retains bounded body text by its separate documented limits.

Validation uses synthetic providers only: actual encrypted Node tests cover full pagination, nested Archive, immutable moves, duplicate RFC IDs, direct/embedded/generated 8 MiB attachments, owner denial, protected/reference content, crash-equivalent restart, partial streams, rollback, retry floors, monotonic deadlines and noncooperative operations. The host API acceptance test calls a real encrypted Node worker. These results qualify offline code behavior; Microsoft tenant consent, real Exchange/Outlook.com mailbox behavior and platform key custody qualification remain EIG-120/EIG-126 concerns. The development registration was not modified.
