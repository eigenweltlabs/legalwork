# Durable drafts and provider synchronization (EIG-143)

Draft editing first writes a separate device recovery record, then saves an immutable encrypted mail-database version using compare-and-swap. The recovery record includes raw incomplete address fields, body formats, attachment references, draft/account IDs and the last acknowledged local version. Main-process IPC encrypts with Electron safeStorage after the existing mail keychain preflight, writes a private temporary file, fsyncs, atomically renames and syncs the containing directory where supported. The journal lives below the desktop userData directory; browser storage never contains a plaintext backup. Graceful quit drains accepted journal writes. A process or OS interruption before the recovery acknowledgment can still lose the last unacknowledged keystrokes; no UI claims they were saved.

Recovery is independent of the mail worker, so worker failure or navigation does not drop acknowledged recovery. Drafts lists these records after the current local server confirms account read authorization; a locked, disconnected or foreign account is not exposed. Reopening tries the preserved CAS version. A conflict leaves both versions available and offers a new local draft. Successful local acknowledgment removes only the matching recovery revision; stale acknowledgments cannot remove newer edits. Missing safeStorage/private permissions, storage failure and the 200-record/24-KiB-content limit are visible failures. Browsers without the desktop bridge rely on normal local saves and receive no device-recovery claim. Existing published attachment bytes remain encrypted and retained; the recovery record stores references rather than duplicating binary files.

## User workflow and states

Synchronization tracks drafts created and linked by this composer. Pre-existing provider-only drafts remain visible through normal mailbox reading; this ticket does not bulk-import them into the local compose list.

In the composer, **Sync** enables provider draft synchronization for that draft. Later local versions queue automatically while the worker is ready; an idle synchronized draft is checked for remote changes approximately once a minute. Local saving continues independently. **Pause sync** stops provider work. Provider conflicts show **Keep local**, **Use remote**, and **Save local copy**; decisions carry the exact observed remote hash and expected local version. Using remote checks again before adopting and preserves the prior immutable local version. A later local edit prevents adoption from replacing newer work. A removed remote draft requires a new local copy to create another provider draft.

**Delete draft** verifies and removes the linked remote draft before tombstoning the same local version. Historical versions and pinned attachment content remain available to internal recovery/submission contracts. It does not delete newer local edits. The older `drafts/delete` API remains a local-only tombstone operation; callers wanting provider cleanup must use `drafts/sync/request` with `action: delete`.

Uncertain dispatch is distinct from failure. The runner persists the MIME bytes, immutable local version, credential generation and unique Message-ID before provider mutation. After restart, it searches for that marker rather than repeating a create. Missing, multiple, changed or unverifiable results remain explicit uncertainty/conflict. Gmail/Graph/IMAP cannot promise an atomic cross-client operation: another client can modify a draft between preflight and mutation, and some providers rewrite MIME. If an acknowledgment was lost and the provider-returned MIME differs from the persisted bytes, the runner cannot prove equivalence and requires explicit recovery rather than guessing. The UI offers pause and a local copy; it does not report remote success. Credential changes retain uncertain state until reviewed.

## Provider conventions

| Provider | Supported draft convention | Boundaries |
| --- | --- | --- |
| Gmail | `drafts.create/get/update/delete`, base64url MIME, stable draft ID plus separately tracked replacement message ID/history ID; marker lookup through draft search. | Uses existing compose/modify/full-mail scope. Update has best-effort read/hash preflight; it is not atomic compare-and-swap. [Gmail draft guide](https://developers.google.com/workspace/gmail/api/guides/drafts). |
| Microsoft Graph | MIME `POST /messages`, immutable IDs, `isDraft` plus MIME reads, and conditional deletion. Shared mailboxes resolve their own `/users/...` target and current declared write grant. | Arbitrary MIME replacement uses verified create-then-delete because JSON PATCH cannot replace a whole MIME message. Both identities are journaled before old deletion; interruption is reconciled. Provider size/policy rejection remains visible. [Graph create message](https://learn.microsoft.com/en-us/graph/api/user-post-messages?view=graph-rest-1.0). |
| IMAP | Exactly one selectable SPECIAL-USE `\\Drafts` mailbox, implicit verified TLS, `APPEND` with `\\Draft`, APPENDUID and UIDVALIDITY mapping, create-then-delete, UID-scoped expunge. | Requires UIDPLUS; never guesses a localized folder or globally expunges other messages. UIDVALIDITY is checked again before deletion; CONDSTORE is used when enabled. Servers without these conventions stay local-only. [UIDPLUS RFC](https://www.rfc-editor.org/rfc/rfc4315.html). |

Incomplete addresses and unsupported MIME remain lossless in the local draft and device journal. Provider sync currently requires the compose serializer's complete ASCII mailbox addresses and at least one recipient; Unicode subject/body/file names are supported. Bounds are 24 KiB local structured content, 20 attachments, 10 MiB per attachment, 20 MiB attachment total and 30 MiB encoded MIME; providers can impose lower limits. The private provider-draft MIME includes Bcc so reopening remotely preserves it. The shared recipient-visible MIME builder still omits Bcc and keeps it in the submission envelope. No send endpoint is introduced.

## Contracts for EIG-145 / EIG-146

Migration 18 adds `mail_draft_sync`; it depends on shared-mailbox migration 17. Routes and worker commands are strict typed inputs:

- `POST /mail/v1/accounts/:accountId/drafts/sync/status` with `{draftId}`.
- `POST .../drafts/sync/request` with `{draftId, expected, action, remoteHash?}`. Actions are `sync`, `retry`, `keep_local`, `use_remote`, `delete`, `disable`.
- `DraftSyncStatus` distinguishes local, queued, syncing, synced, conflict, uncertain, error and removed. `remote` includes provider draft/message IDs, version, and IMAP folder/UIDVALIDITY where applicable.
- `DraftSyncStore.cleanupAfterSend(accountId, actionId)` is an internal hook. It requires a **succeeded submission action** and immutable draft pin matching the last synchronized version in a stable synchronized state; it schedules verified remote cleanup. Call the hook after the submission journal records a confirmed outcome, then wake the runner. `false` means no matching remote mapping: the sending implementation must apply its own pinned local-draft cleanup. A newer local version survives. There is no renderer-provided “sent” flag.
- EIG-145 must resolve its verified sender identity before `buildMailMime`, supply its authorized address and report sender unavailability. This ticket does not introduce sender settings or perform provider submission.

## Focused evidence

Synthetic encrypted Node SQLite tests cover restart mapping/history, lost create/delete acknowledgments, no uncertain duplicate create, incomplete drafts, explicit remote adoption, copy replacement cleanup, edits after reconciliation, account ownership and trusted send cleanup. HTTP adapter fixtures cover Gmail draft/message identity, Graph shared target/MIME/conditional delete, authentication failures and hostile pagination. IMAP fixtures cover folder/capability conventions, APPENDUID, CONDSTORE and UIDVALIDITY fencing. Native journal tests verify ciphertext, stale-ack safety, reopen, authorization filtering, preflight/permission and malformed input rejection. Isolated hidden Electron UI tests exercise compose regression and sync/conflict/uncertainty controls with synthetic transports. No live account, regular desktop profile, full app suite, platform build, or final provider certification was used.
