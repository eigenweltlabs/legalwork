# Mail security review (EIG-154)

Review began from `432e24fd9` on macOS 15.6.1 / arm64 with Node 24.11.0 and the existing installed Electron. This is an implementation and malicious-fixture review of mail, not an independent penetration-test certificate or a claim that the entire application/dependency tree is vulnerability-free. Profiles, tokens, messages, paths and accounts in these tests are synthetic. No live mailbox was changed, no normal desktop profile was opened by the tests, and no full application/platform suite ran.

## Confirmed fixes

- **Image attachment preview bypassed the decoded-dimension gate.** MIME/signature checks alone let a tiny file declare an oversized raster before the shared viewer created a blob URL. `openMailPreview` now checks the existing raster gate before replacing an already verified tab. Dimensions above 4096 per axis or the pixel budget, SVG, and MIME mismatches are rejected; saving the original remains available. Commit `fa152e05c`.
- **GIF/APNG frame amplification was missing from image budgets.** The previous gate counted only the canvas once. Small, valid two-frame GIF/APNG fixtures are decoded by actual Chromium to establish that this is an animation path. The gate now bounds GIF frame blocks and APNG controls, checks subframe rectangles and the PNG IHDR, rejects truncated/inconsistent containers, caps declared frames at 128, and conservatively charges every full canvas (plus APNG's default image). The 4,194,304 per-image and 16,777,216 page/remote-operation pixel budgets include that charge. No oversized image was decoded during testing. Commits `eebd9f106`, `e753cf300`.

These frame/canvas budgets bound admitted encoded work. They are not a measurement or upper bound on Chromium's additional decoder buffers, compositing/GPU allocations, or total RSS. Animated WebP remains unsupported as before.

A suspected Word-font request was **not reproduced**: the exported `DocxReviewer` already disables font preloading, unlike another API in the same package. Actual Electron accepted a sender-selected unknown font without attempting any HTTP(S) request, and rejected an encoded external relationship. The existing parser was preserved; its negative fixture is retained. `083c8b3ae` makes that fixture use the installed Electron and independent temporary entries.

## Matter and agent access

EIG-148 review covered `29d6ab9e9` + `dc3235d60` (root integrated the complete runtime at `df9c2a4f2`) and LegalMemory `e55c356` + `e42a9a7`. Source-version digests bind the current raw/body/projection/attachment metadata and hashes; one-shot, bounded search scopes verify those versions before counts/snippets. Imported provenance and generic storage receipts are not matter authority. The backend derives identity from authenticated transport, checks explicit denies before write/read authorization, uses separate document-version read checks, verifies hashes, and commits receipt/document/matter associations atomically. Deduplication does not grant access to another matter.

Shared-storage connection revision checks and separate backend ACL RPCs are preflight fences, not atomic guarantees across services; the implementation documents that limit. [Shared storage PR 131](https://github.com/eigenweltlabs/legalwork/pull/131) and [LegalMemory PR 23](https://github.com/eigenweltlabs/LegalMemory/pull/23) remain separate unmerged/undeployed prerequisites. Synthetic contract evidence does not certify a deployed composition.

EIG-149 review and the targeted negative checks covered final commit `8f4de4646`. The inspected implementation uses a separate opaque capability endpoint: host-only provisioning binds the account, canonical task workspace, account credential generation, optional matter, permissions, expiry and grant revision. Caller account/workspace overrides, unknown tokens, origins and foreign tasks fail before reads. Capability bearers remain in private engine provisioning files and never appear in tool results or model arguments. Source versions are checked after awaited data reads and inside draft/approval transactions. Agent drafts are plain text without caller attachment references; send/trash tools create immutable proposals requiring a separate host-user review. The outbox transaction pins the reviewed draft, and the trash transaction now rechecks the reviewed message hash before enqueueing.

Mail text is explicitly returned as untrusted data. The deterministic protection is the grant and separate approval boundary, not that a model can never follow hostile prose. Grant-authorized mail can enter the task transcript and its configured model; the UI discloses this. The managed engine's arbitrary local shell/code tools are **not** confined by mail grants and can act with the OS user's privileges. A private per-directory capability file is not an OS sandbox or containment against a compromised engine. These limits must remain visible in the agent-access documentation.

## Dependency and notice review

`pnpm audit --prod --json` on this pinned workspace reported **143 advisory findings** (1 critical, 67 high, 65 moderate, 10 low), across 1,328 reported dependencies including optional packages. This is not a clean whole-app audit. Mail-specific MIME/SQLite/HTML/image/extraction roots had no reported direct advisory in this response. The Word editor dependency graph contains affected `@xmldom/xmldom` and AI SDK utilities; inspecting the actual read path found the browser preflight plus `xml-js` parser, while template-processing APIs reach xmldom. Package presence alone is not treated as a demonstrated mail exploit, and no mass upgrade was made. Other application surfaces and the installed Electron/Chromium update cadence need their own release review.

The current [xmldom attribute-deduplication advisory](https://github.com/xmldom/xmldom/security/advisories/GHSA-8344-3jmq-59r6) illustrates why compressed byte bounds alone are insufficient, but it was not reproduced as this mail reader's parser path. [Electron security guidance](https://www.electronjs.org/docs/latest/tutorial/security) recommends current framework versions and process sandboxing. The main/session windows currently have `contextIsolation:true`, `nodeIntegration:false`, **`sandbox:false`**, with an ESM preload; [Electron's ESM documentation](https://www.electronjs.org/docs/latest/tutorial/esm) explains the preload constraint. A whole-app preload/sandbox migration is explicitly deferred to EIG-152/174; the opaque mail frame is not described as OS sandboxing.

`apps/app/scripts/mail-license-notices.mjs` generates `public/third-party/mail/DEPENDENCY_LICENSES.txt` from 78 pinned mail dependency packages. It supplements existing office-editor notices, includes DOMPurify 3.4.15/CSS Tree and separately licensed PDF.js assets, and retains available upstream notice texts. Three small vendored upstream notice files cover omissions in published packages. The Tesseract language package declares MIT for its package, while its distributed trained data comes from [the Apache-2.0 tessdata repository](https://github.com/naptha/tessdata); both facts are preserved rather than relabeling the model MIT. Optional platform binaries retain their bundled notices. Actual packaged-resource verification remains EIG-152. No GPL application reference implementation was copied.

## Disposition

The two demonstrated image admission defects are fixed, and the final EIG-148/149 access surfaces are covered by source review and the focused negative checks above. No unresolved demonstrated mail exposure or unauthorized mail action remains from this review. This conclusion is limited to these paths and fixtures: it does not clear the whole dependency audit, replace independent penetration testing, or certify the undeployed LegalMemory/shared-storage composition. EIG-152/173/174 retain packaged dependencies, supported OS/keychain behavior, real-provider operation and broad application qualification. No production account, remote send, or provider mutation was used as security-test evidence.
