# Durable outbox (EIG-146)

Send saves and pins one immutable local draft version, serializes MIME and the private recipient envelope, and persists them with a stable Message-ID in encrypted mail storage before dispatch. Repeated clicks for the same version return the same action even with a different replay key. The existing action journal owns attempts, cancellation, leases and the durable dispatch boundary. Existing submission API calls also pass through serialization.

Queued/preparing work can be cancelled before dispatch. Once dispatch begins, cancellation cannot retract mail. A crash, connection loss, sleep or timeout after the boundary produces **uncertain**, never automatic resend. Outbox offers a read-only Sent check; absence is not evidence of rejection. Only explicit provider rejection or failure before dispatch permits retry of the same immutable MIME. Retrying rechecks current connection and sender permission. A new draft is required to change recipients or message content.

Accepted means the outgoing server accepted submission, **not delivered**. SMTP RCPT partial acceptance is displayed per rejected address using status codes only. The original draft is retained for partial acceptance, uncertain recipient outcomes, unconfirmed Sent copies and unsettled remote-draft mapping. Later bounces/DSNs remain ordinary incoming messages; this release does not claim delivery tracking. SMTP requests failure/delay DSNs where supported.

## Providers and limits

- Gmail: authenticated `users.messages.send` media upload, `message/rfc822`. Private MIME contains Bcc; SMTP MIME does not expose Bcc headers. Gmail manages Sent copies. Verified sender identities are rechecked at dispatch.
- Microsoft: `/me/sendMail` MIME for requests up to 3.9 MB after base64 encoding. Shared/delegated From is explicitly preserved; Exchange determines actual Sender from granted SendAs/SendOnBehalf rights. `/me` saves Sent in the signed-in account and avoids requiring FullAccess solely to send; Exchange policy may add a shared-mailbox copy. Declared rights are not represented as server-verified.
- Primary Microsoft larger messages: create a MIME draft with the fixed Message-ID, attach files using bounded JSON requests or upload sessions, upload in 2 MiB chunks to the allowlisted preauthenticated Outlook URL without a bearer header, then send the prepared draft. Interrupted preparation is retained as an explicit preparation failure and never automatically recreated or sent; review remote Drafts before making a replacement. Upload-session bearer URLs never reach the renderer. Large shared/delegated requests and inline images of 3 MiB or larger are explicitly unsupported because of Graph API constraints.
- IMAP accounts: separate SMTP Settings use implicit TLS or **required** STARTTLS, verified certificates, authenticated connections and no plaintext fallback. Passwords remain in encrypted worker custody; settings responses omit passwords. Saving settings does not claim authentication was verified. Reconnection invalidates their generation; disconnection removes outgoing credentials. SMTP SIZE is supplied to enforce advertised server limits before message transfer.
- Existing composer limits apply: 10 MiB per attachment, 20 MiB total attachments, at most 20 attachments, 30 MiB serialized private MIME. SMTPUTF8 addresses and large inline Graph uploads are not advertised as supported. Provider/account limits may be lower.

SMTP Settings explicitly choose provider-managed Sent copies or LegalWork IMAP APPEND. APPEND occurs only after accepted outcome is durable, searches for an existing exact Message-ID/sender first and never repeats an ambiguous APPEND after restart. Unknown SMTP sends use read-only IMAP Sent lookup with the same exact match and never APPEND. Missing, multiple or mismatched messages remain uncertain. Successful SMTP Sent reconciliation retains the draft because individual recipient acceptance was not recovered.

Trusted EIG-143 cleanup runs only after the succeeded submission journal and pinned version exist. Matching stable remote drafts can be cleaned up; newer local edits and unstable/missing remote mappings survive. User Pause mail and OS sleep suspend/abort the runner through EIG-147 lifecycle hooks; initialization in paused state cannot briefly dispatch. Resume starts only safe queued work. Nothing sends while the application is closed or the computer is off.

## Focused evidence

`pnpm exec node apps/server/scripts/mail-acceptance.mjs --suite storage/outbox` covers encrypted schema upgrade/rollback/reopen, immutable pin/MIME, repeated clicks, acceptance/restart, lost acknowledgment/Sent recovery, cancellation, sender revocation, explicit retry, partial acceptance, SMTP custody, real private-worker queue/restart, paused startup and crossed-dispatch suspension.

Provider suites `providers/http-submit`, `providers/smtp-submit` and `providers/sent-copy` exercise synthetic HTTP contracts, bounded Graph uploads, fixed provider/upload hosts, implicit TLS, actual STARTTLS, rejection without TLS, partial SMTP recipients, lost DATA acknowledgment and read-only Sent matching. The SMTP fixtures generate an isolated CA/certificate and inject trust only into the test connection factory.

`pnpm exec bun test apps/server/src/mail/runtime/outbox-protocol.test.ts apps/app/tests/mail-outbox.test.ts` checks secret-free protocol responses and a hidden Electron renderer: SMTP Settings, cleared password, permitted sender, durable version queue, double-click deduplication and uncertainty controls. Temporary profiles are isolated from the user's app.

Actual Gmail, Microsoft self/shared/delegated and IMAP/SMTP account sends, alias headers, Sent copies, provider limits and cross-platform packaging certification are the final EIG-173 gate. No real provider send or user profile was used for this ticket.
