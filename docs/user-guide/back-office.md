# Back Office

Open **Back Office** from the global sidebar. Choose **Matters**, **Clients** (German: **Mandanten**), **People** or **Organisations**. **Create** and **Add New** add a row immediately and open its name in the right-hand panel. Type a name and press **Enter** or click another field to save the name. For a custom model with additional required fields, fill them in to finish saving the row. Firm sync runs in the background. Large directories download in pages. Once caught up, each computer receives the records that changed. Choose **Create and select** inside a relationship field to create and link a record in one step. Click a grid cell to edit an existing record. Changes to different fields merge automatically. If two edits compete for the same field while you are editing, the panel shows both values and lets you choose which to keep. Archiving preserves edits to the record’s fields. Relation pickers connect existing records. Changes to views stay inside the current screen. Back Office follows the app’s appearance setting, including Dark, Blackout and System. Tables, menus, record panels and dialogs use the same theme.

Open **More > Tasks** or **More > Deadlines** for the same records used by Tasks and Calendar. Open **Tasks** in the sidebar for the task list, sessions, files and workflow actions. In **Calendar**, choose **Deadlines** to switch to the table. Project tables show that project's records.

Click a cell or open the name to edit in the sidebar. A task's status, priority, assignee, due date, tags and description update the original task. Deadlines use their project's calendar, reminders and history. Moving a calculated deadline asks for an override reason. Under **Data model**, both schemas are locked.

In **Linked records**, search for a matter, client, person or other Back Office record, including custom record types. You can also open a Back Office record and use **Tasks and deadlines** to link or unlink from that side. Sharing a link requires both records to be available to that colleague. Native table views you save are personal to this device and account.

Matters use a briefcase icon, Clients a group, People a person and Organisations a building. The same symbols identify these record types in Project Home, project filters, field configuration and creation dialogs. Custom record types use a database icon.

Background updates keep an open field's draft and the version you started editing. If saving fails, the input stays available; correct an invalid value or retry after a connection error. Background sync merges independent changes. If two people enter different values for the same text field, choose which value to keep. Changes to a saved view also check the settings you started from. Updates to different view settings merge automatically. If the same setting changed twice, choose which edit to keep.

For a project metadata reference, click a selected name to change the selection. The small arrow beside it opens that record. Searchable pickers show plain option names and a checkmark beside selected rows. For fields that allow several values, click a row to add or remove it. Each click saves immediately and the picker stays open.

If a related record is missing, choose **Create [record type]** at the bottom of its picker. This works in table cells, record panels, other views, project metadata and record-based project filters, including custom objects. Your search text supplies the starting name. Pickers use a short form so you can create a related record and return to your selection. Matter forms initially show Name, Clients and File number; **More details** reveals the remaining fields. File number is the existing Back Office field, not a separate project field. Your firm can change the short form as described below. Required fields and fields constrained by selection rules always remain visible. Relation choices support search, arrow keys and Enter and update the draft immediately. Matter searches also match clients and file numbers, with recently selected matters first. You can create another related person or organisation from inside this form without losing the parent draft. Choose **Create and select**, or press **⌘Enter** on macOS (**Ctrl+Enter** elsewhere), to save the record being created. Plain Enter in its name does not create it. The new record appears first and selected in the picker. **Create and select** also keeps existing choices in a multi-record field. Existing records are linked or unlinked as you click. Your selection stays in place while the firm directory syncs.

In **Create project**, choose a template below the project name. The **Legal Matter** template offers **Add Matter** and **Add Client**. Select an existing record or create one in the picker. See [Projects and sharing](projects-sharing.md) to configure these buttons.

**Back to selection**, **Cancel** and Escape return without saving the current draft. Records you already created in a nested form remain in Back Office if you later cancel the parent or its assignment. Record creation does not create a project assignment until you select/apply it. In a project-list filter it changes the filter choices, not any project's metadata. Configure eligible records under **Selection rules** using the labelled **Field**, **Condition** and **Value** controls. The matching count previews the choices available on Project Home. A filtered metadata field offers allowed select options and supplies unambiguous filter defaults; you must choose between several allowed types. The new record must satisfy all applicable filters. Creation follows your current permissions and is not offered for hidden internal tables or inaccessible object types. A changed directory or validation error keeps the existing selection.

Clients link directly to a person or an organisation. There is no separate Client type to keep in sync with those links.

A table scrolls continuously through its records. Search, filters, sorting and column totals cover the full result set. **Select all rows** selects every matching record, including rows below the screen. Check the selected count before choosing **Archive** or **Restore**.

### Filtering records

Use **Search records** beside **Filter** to search the current object's readable fields, including linked record names. Results update as you type and combine with active filters. The × in the search box clears the search. Search stays visible in Table, Kanban, Calendar and List.

Choose **Filter** above the records. The first row starts with **Name** and **contains**: enter text, then choose **Apply filters**. Change **Field** to another accessible property and choose its **Condition** and **Value**. Type in the field picker's search box to find a property. Text, numbers, dates, Yes/No fields, linked records, selection fields, currency amounts and files are supported. Linked-record values use the same searchable picker as table cells. Currency filters include an explicit three-letter currency; comparisons use that currency only. File filters match filenames or check whether a file exists.

Choose **Add filter** for more conditions, then **All rules** or **Any rule**. The preview count shows the result within the current search and archive selection. **Apply filters** updates the records; cancelling or closing the panel keeps the applied filters. Active filters appear above the records. Click a filter's × to remove it, or choose **Filter > Clear filters** to remove all of them.

Filtering applies to Table, Kanban, Calendar and List. For a saved view, choose **Options > Save view** to retain its filters, or create a view with the current filters. Private notes are not offered as shared-view filters; financial fields follow your billing access.

### Working with the assistant

The assistant can link record names in its answers. Click a record link to open that item in Back Office.

The main Assistant and ordinary project chats can read and update Back Office records, including custom objects. Ask for the result you need, for example, “Create a project for this client's acquisition and connect the client and matter.” The agent discovers your current model and project fields, checks for existing records, creates missing records supported by your request or sources, and links them through project metadata. It verifies the saved links before reporting completion. Creating a project does not automatically create billing records or fill unknown details.

The same workflow applies when a project chat sets itself up from documents or receives delegated work. Records are shared CRM items; linking them to another project keeps their identity. The agent preserves existing values, respects each field's selectable-record filters and asks about ambiguous identities or missing required facts. Custom People types remain ordinary editable options. Changes to the model itself are a separate requested action with a preview for affected records. Back Office and project permissions still apply.

Use **Filter**, **Sort** and **Options** to control the table. Drag column headers to reorder them and drag their borders to resize them. Open the view selector, such as **All Matters**, then **Add view**. Name the view and choose **Table**, **Kanban**, **Calendar** or **List**. Kanban requires a select or single-relation field for its stages. Calendar uses a date field and supports day, week and month. Saved views keep their layout, columns, search, filters and sort. Switch views in the selector without reloading the page. A saved view’s options allow editing its name and configuration or deleting it. Deleting a view keeps its records. Use **Options > Save view** to update the selected view’s current filters and columns, or **Add view** to save another view. Use **Search records** beside **Filter** to search the current view. **Options > Show archive** displays archived records. Open a record's **Record options > Restore record** to restore it.

Drag a Kanban card onto another stage to update its grouping field. The card moves on release while LegalWork saves the change. If the save fails, the board shows the current stored stage and an error. Press **Esc** before releasing to cancel a drag. Calendar cards can be dragged to another date, which updates the selected date field. Use a calendar day’s plus button to create a dated record. Creation and update timestamps are read-only. Cards and list rows open the same record panel and use the same field editors as Table.

The default **Legal Matter** template has optional **Matters** and **Client** links. Matter number, status, practice area and matter clients live on the linked matter. Use **Client** for a direct project assignment. Untouched starter templates update for future projects. Saved project values and customized templates are preserved.

On **Project Home > Project details**, click **Not set** or the current record name to open the same searchable dropdown as the Back Office table. Choose a record or create one there. A single selection saves immediately. For multiple records, each selection saves immediately. Clients of linked matters appear with **via [matter name]**. Several projects can link the same record.

Choose **Customize fields > Add field** for a custom role or field. A People field named Witnesses selects People records. Under **Selection settings**, set the selection rules, allow multiple records, or enable **Show as a quick action**. Each shortcut fills that specific field. The arrow beside a linked record opens it in Back Office. Its × removes the project link.

**Organisations** includes companies, courts, public authorities, law firms, associations and other institutions. Use **Organisation type** to distinguish them. Clients, people and matter parties can refer to an organisation.

Open **Data model** to manage visible objects and fields. Choose an object, then **New field > select a type** to configure a custom field. Protected fields retain the types and relationships LegalWork needs. Labels remain editable. Changes affecting existing records show a review before applying. Changes that would invalidate stored values remain blocked. **Settings** edits the object's names and the fields shown in its creation form. Custom objects can be archived and restored. **Add object** creates another directory type with a required Name field.

### Choose the fields in short forms

Open **Back Office > Data model > choose an object > Settings**. Under **Fields shown when creating a record**, select the fields that should appear immediately, then **Save**. Other fields remain under **More details**. Required fields cannot be hidden. This configuration controls the short forms in project and relation pickers. The record sidebar shows the full list of properties. The initial Matter selection is Clients and File number in addition to the required Name. Editing the data model requires model-management permission. Team configuration requires a platform version that supports this setting.

### People and types

People includes internal team members and external contacts in one directory. **Type** is a normal select field: Partner, Counsel, Associate, Assistant, Operations, Freelancer, Other team member and External contact are starting options. A model editor can open **Data model > People > Type**, edit **Options, separated by commas**, and save additional types. The assistant can also update the model. Types are not tied to employee status or app permissions.

New people start with **Active** enabled and Type set to External contact when that option exists. Choose the actual type explicitly. Existing people keep their existing details and assignments; the upgrade enables Active without guessing their type. Set Active to false when someone should stop appearing in new active-team assignments. Existing project links remain readable.

### File fields

Fee agreements have **Signed agreement**, and invoices have **Invoice PDF**. For another attachment field, open **Data model > choose an object > New field > File**. Enable **Allow several files** for up to 20 attachments in a custom field. Each file can be up to 10 MB.

Click a file field and choose **Attach a copy**, or **Choose from a project** to browse an existing project file. This creates an immutable copy with its own identity. Its access follows the Back Office record and field; the original file and its project permissions stay unchanged. Uploading a replacement creates a new version identity. Click the filename to preview the attached version in the document viewer, or choose **Download**. The preview is read only. Removing an attachment from a field does not delete the original project file.

Files work locally without a platform update or team sync. With firm sharing enabled, the verified attachment bytes are uploaded before the record references them. Other authorized computers download and cache the same version when it is opened. Financial and private fields keep their existing restrictions. CSV export includes attachment names. Full document-management workflows remain separate.

To import many records, give the assistant your source data and tell it which records to create and how they relate. It can prepare the rows in a script and save up to 500 records per request across standard or custom CRM models. If a row fails validation, the entire batch is rolled back. Earlier completed batches remain saved. Use **More actions > Export CSV** to export the records and fields you may read.

Back Office opens one directory automatically. When a platform administrator enables Back Office sync, it uses the firm workspace and syncs subsequent edits automatically. With sync disabled it uses local records. Open **More actions > Team sync** to review sync status and queued edits. Back Office team sync is on by default for subscribed firms. An administrator can turn it off under **Policies > Sharing** on the platform. When sharing starts, your desktop automatically uploads records created under your firm account and keeps existing project links. Records waiting for their first sync appear in the Back Office table on the source computer with **On this computer** beside their name. Edit these rows directly on this computer. Choose **Team sync** to review sharing. File attachments become available in the firm directory after the record is shared. If records on this computer have no firm assigned, open **More actions > Team sync** and choose **Share with [firm name]** only if those records belong to that firm. Records requiring additional permissions or compatible fields stay on the computer. Shared project links require the project to be shared with that firm. Project permissions remain independent of matter links. Administrator permissions separately control editing records, customizing the data model, and access to billing data such as rates, time entries and invoices.

Offline record edits remain queued. Model changes require an online connection. Open **More actions > Team sync** to compare your edits with the team version. **Apply my changes** reapplies the reviewed fields to the latest team record. If that record changes again, review it again. **Discard queued edit** removes that record's queued edits and reloads the team version after confirmation. If access is revoked, the managed replica is cleared while queued edits remain available for resolution. Signing out warns about pending changes.

The starter model includes fee agreements, time entries, billing items and invoices under **More** as data foundations. Currency amounts are kept separate by currency. A matter's value in dispute describes the case value. Private work notes, client-facing narratives and financial fields have separate access rules. Open **Time** to record work, review submitted entries and issue invoices.

### History and verification

Open a saved record and choose **History** beside **Home**. Entries show who made each change, when it was recorded, and the previous and new values using the field definitions from that time. **Load earlier entries** shows older revisions. **Entry details** shows the model version, identity source and proof fingerprint. Archived records keep their history; use **Options > Show archive** to open one.

Click an attachment filename in **History** to download the version from that revision, including a version removed from the current record. Your current and historical access rights still apply. Removing a file reference does not overwrite its earlier bytes.

History and exports apply both historical and current access rules. Model administration does not grant access to financial fields or somebody else's private notes. Restricted related matters and projects stay restricted. Some original details may therefore be hidden. A record's history is unavailable after its access is revoked. A dated baseline identifies existing data captured when this history system was enabled; it does not claim that earlier activity was verified when it occurred.

Choose **Export history** to download signed JSON containing the authorized selection, proof chains and the number of original payloads withheld. It includes previous values that you are authorized to read. Keep the JSON unchanged for verification. It is a history selection, not a complete database backup, and does not include attachment bytes. The assistant can inspect record, model and saved-view history, export a selection, or verify an existing export separately from the current Back Office history.

**Verification** explains where signatures were checked and whether an independent checkpoint has been acknowledged. Signatures make changed entries detectable. Separately retained, trusted checkpoints also help detect a restored older copy. Verifying an export against checkpoints copied from that same export establishes consistency, without independent rollback evidence. Retain Back Office history exports and trusted checkpoints separately according to your firm's evidence-retention process. This protects Back Office changes, not other app activity. Local verification cannot independently detect replacing the whole computer's database, keys and checkpoints together.

Local record history works without team sync or a platform connection. Shared history shows accepted team changes, uses current platform permissions and requires a supporting platform version and a connection. Pending edits remain in **More actions > changes pending** until accepted. An older or unreachable platform does not cause LegalWork to substitute cached team history for an authorization check.

If your firm removes record or field access, LegalWork clears those copied values from its managed record and history cache. The firm history is checked with your current permissions. Queued edits keep the fields you actually changed, with inaccessible fields removed and affected drafts held for review. A disconnected team directory retains only the remaining plain authored fields for review; copied file/relationship details and privileged values are removed from those proposals. Reconnect with permission before sending them.

Queued drafts belong to the account and platform that created them. Switching accounts clears managed team records and history from the previous connection. The remaining plain fields you authored stay held for review, and another account cannot send or discard them. Sign back in with the same account on the same platform, open **Back Office > More actions > Team sync**, and compare them before choosing **Apply my changes** or **Discard queued edit**. Drafts from older builds without a recorded author are preserved outside the automatic sync queue. An administrator must investigate and manually re-enter authorized changes; the app does not assign these old drafts to a new account.

### Enter, copy and correct time

Open **Back Office > Time > My time**. Choose a work date, or switch the date filter to a week to enter several days together. The small figures above the list show worked time, billable and non-billable work, and the chargeable quantity after billing adjustments.

Start in the input row. Type a client name, matter or file reference, choose an activity, and enter a narrative and minutes. Tab advances through the row. Enter on a completed new row books it. The next row keeps the date and matter. DFT creates a work product. MOD suggests products already recorded for that matter and accepts a new title. If two documents have the same title, select the specific result using its author, creation date or ID. To start a second document under an existing title, use **+ (Create a separate work product)** in the Work product cell, enter the title and book the row. A copied row keeps its original product ID. For a shared meeting, choose the participating workers. The creator and the person who performed each line are recorded separately. Each colleague can confirm their own entry before submission.

To reuse a whole row, select it using its row selector, press **⌘C / Ctrl+C**, choose the target day, then **⌘V / Ctrl+V** in the list. Edit the draft before saving. It starts under the current worker and target date and retains the matter, work product, activity, narrative and durations. A new copy has its own identity and history. You can also duplicate the selected row from the toolbar. Click an editable cell to correct a saved line in place. Escape discards the pending edit. The history action shows the previous and current values.

### Reconstruct a workday

From **Back Office > Time**, open **Workday > Sources and schedule** on the local LegalWork server. Enable **Project calendar** and/or **Completed dated tasks**, select the date and use **Read selected sources**. A task without a known duration leaves the duration blank. **Edit in list** opens a private proposal as an editable row. Saving creates the billing record. Dismissing a proposal excludes it from subsequent preparations for that date.

The time axis shows timed proposals in the matters for which there is evidence. Recorded work has its own column. Proposals without a time range remain in the list. If intervals overlap, use **Correct** to check the actual time before opening the proposed entry in the list. Choose **Correct** to adjust the description, matter, clock range or duration before booking. **Move part to another matter** assigns the final minutes to a second matter, with both actual durations and charge options previewed. Save the correction and book each part separately. Both can be compared with the private original in entry history. For spoken text, use a keyboard dictation mode configured for offline processing on the device.

To include a connected source, first connect and activate the account in **Integrations**. Enable its source separately in **Workday > Sources and schedule**. **Google primary calendar** and **Outlook primary calendar** read calendar titles and times for the selected date. **Gmail sent messages** and **Outlook sent messages** read sent-message subjects. A mail reminder has no duration or assigned client. Enter those in the list before saving. Disconnecting or deactivating an account hides its reminders. Workday currently has no operating-system-wide active-window collector on macOS or Windows.

For model-assisted drafting, configure the local server environment with absolute paths in `LEGALWORK_TIMESHEET_LLAMA_CLI` (llama.cpp CLI) and `LEGALWORK_TIMESHEET_GGUF` (local text-generation model). Restart the server, then choose **Suggest with local AI**. **Workflows > Suggest Timesheet** controls the drafting instructions. The runner reads the installed workflow for each run and uses the model in offline mode. A 15-, 30- or 60-minute interval prepares the current workday while the local server runs. Unconfirmed narratives and the original proposal versions stay in this device's private workday storage. The confirmed entry carries its proposal digest. The calendar can also be used without installing a model.

### Set billing rules, review fees and issue invoices

Open the view selector beside **My time > Billing settings**. Choose firm, client, matter or project and an effective date. A project can inherit its client’s increment or set an override. **Enforce billing increment** applies to each positive chargeable line. At ten minutes, a line can be 10, 20 or 30 minutes. Disabling enforcement allows individual minute amounts. Actual time is kept separately. **Proposed rounding** can suggest the next, previous or nearest unit in the charge cell. The default leaves the choice to the worker. A line above the applicable activity limit can be saved and submitted in full. It is marked for review until the charge or applicable exception is resolved. Set activity limits, narrative language and wording, rates, currency and the reviewer. At firm level, **Activity codes and labels** adds firm-specific choices to the time-entry list. Saved revisions retain the label in force at the time. **Opening words by activity** specifies how a description begins. **Preferred wording, spelling and abbreviations** supplies replacements. During review, accept or dismiss a proposed correction beside the submitted wording. For one-person local practice, explicitly enable solo approval before approving your own work. For a connected firm, the platform must support the timesheet service and authenticated approval.

To correct a previously approved or invoiced entry, open its own history in **My time > Request correction**. Enter the new description or chargeable minutes and a reason, then choose **Send for approval**. The submitted request keeps the original and worked duration intact.

Submit the entries in the personal list. In **Time > Billing review**, select a matter and period, filter to wording or billing exceptions, and click the narrative or charge to edit it. Open the row history to compare the submitted version and review changes. Select the exact rows to approve. The footer gives the selected fees, grouped by currency. The work-product view shows contributions across workers visible to the reviewer. Expand a work product to rename it, choose its type or add a document or email reference while retaining all linked entries. New products retain their creation date and author. Open **Adjustments** in Billing review to compare the original and requested terms. Approve or reject the change with the amount in view. An approved post-issue adjustment creates a separate downloadable note linked to the original invoice.

In **Billing settings > Firm > Invoice template**, set the document title, language, letterhead and payment footer. In **Billing review**, choose approved entries for one client, matter and currency, inspect the preview and issue the invoice. The preview uses the firm template. A number is assigned only at issuance. Reopen the issued HTML document from the invoices list. An issued copy retains the wording, quantities and template used at issuance.
