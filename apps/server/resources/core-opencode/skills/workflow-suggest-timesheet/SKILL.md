# Suggest Timesheet

Use legalwork_timekeeping_workday in the Timekeeping chat. Read the selected date, its existing entries and its suggestions. Read the effective guidelines for each matter before assigning work. Publish each completed draft or related batch to the timeline and finish the review using the latest revision. Look across the whole day for work that belongs together, distinct work within one observed interval, and observations that do not support any entry. Preserve concurrent work when independent observations support each activity. A meeting for one matter and active work on a document for another can occupy the same clock time. Never assign one observed portion of the same source twice. Keep ambiguous assignments and uncertain time open. Calendar appointments and foreground intervals can support a proposed time. An open background window or a background agent run gives context but does not establish human time. A completed task, sent email or attributed file save dates one action. An incoming email can provide context for a reply in the same thread. Its delivery does not show that the worker opened it or spent time reading it. When related dated actions or a substantive change description support a duration estimate, suggest minutes separately and explain the evidence to the reviewer. Leave the clock fields empty. A single title or an idle interval gives too little information for an estimate.

Write one concise invoice sentence describing the human action and the subject in terms the client understands. A task completed during work on a matching document can establish what the person did. Combine related steps and count their observed time once. Keep filenames, internal tags, apps and placeholders out of the billing narrative. Omit activity too vague to describe. Use the billing language, action words, and terminology supplied for the validated scope. For DFT or MOD use the stable document ID and preferred billing title. Use a specific change description only when the evidence or the worker supplies it. Keep personal details out of billing narratives. Apply the worker’s requested changes to an unaccepted suggestion with update_suggestion using its current key, digest, draftRevision and only the requested fields. Previously edited suggestions and stopped timers remain editable even when replaceable is false. To remove a private suggestion, check read.removable on that suggestion and use publish.remove with the current day revision. Agent-only amendments do not block explicit removal, even when replaceable is false. Direct user edits remain protected; later agent edits do not remove that protection. Accepted entries use remove_entry and require human confirmation. Set recordedMinutes when the worker supplies a duration, without inventing clock times. Keep the existing suggestion and its evidence: do not require acceptance, remove it or create a duplicate to edit it. Re-read the day to verify the result. Use the supplied client or matter guidelines and confirmed descriptions for the same document.

In the Timekeeping project chat, use the timekeeping workday tool to read or publish the requested day’s suggestions. Apply a requested recurring preference through the normal project instructions or a project version of this skill. In the main Assistant, delegate to the Timekeeping chat when the user asks. The user reviews proposed entries in Time entries. When the user explicitly asks to edit, translate or remove saved time entries, use list_entries for the requested service date. Use update_entry with only the requested fields (narrative for translations) or remove_entry with each row's exact ID and revision. Removing saved time requires one-time human confirmation in the chat. Never bypass that confirmation or retry a denial without a new user request. Unaccepted private suggestions can be revised with update_suggestion without that confirmation. Read the affected date again to verify which rows changed. On conflict, compare the latest row with the requested change before retrying. Report any locked or conflicting entries individually.
